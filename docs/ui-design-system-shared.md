# AI Food Diary 跨平台 UI 设计规范

> 深度模式总审核版｜Web（Next.js）+ Android App（Flutter）
>
> 本规范整合 8 份需求、研究、形态、视觉、信息架构、交互与内容报告。它定义共享的 Design DNA 和平台化规则，不要求 Web 与 Android 复制页面布局，也不包含生产代码实现。

## 1. 产品定位与设计目标

### 1.1 产品定位

AI Food Diary 是一个 AI 辅助的跨平台饮食记录工具：用户可以拍照、从相簿选择或手动输入餐点，AI 将内容整理成**可编辑草稿**，用户检查并确认后保存为饮食记录，再通过每日反馈、营养趋势与健康数据持续理解自己的饮食节奏。

### 1.2 目标用户

- **大众日常健康用户**：希望低负担地知道今天记录了什么，并获得简单、非评判式的下一步建议。
- **健身与营养进阶用户**：关注热量、蛋白质、脂肪、碳水、份量、目标差距、历史趋势和数据来源。

默认体验采用“摘要优先、详情渐进展开”：不要求普通用户先理解营养学，同时为进阶用户保留精确编辑和趋势详情。

### 1.3 品牌承诺

1. **记录不是负担**：拍照、手动输入和修正都应轻松。
2. **AI 是助手，不是裁判**：AI 只提供估算与建议，最终决定权属于用户。
3. **数据服务于行动**：每项摘要都应帮助用户知道下一步可以做什么。
4. **温暖而可信**：有食物温度，但不医疗化、不制造焦虑、不用游戏化羞辱用户。
5. **共享语义、平台化体验**：Web 与 Android 说同一种产品语言，但遵循各自平台习惯。

### 1.4 非目标

- 不提供医疗诊断、疾病治疗或绝对准确的营养结论。
- 不将未确认的 AI 结果自动写入正式记录。
- 不让 Health Connect 授权成为饮食记录的前置条件。
- 不在本阶段实现或重构 Web/Flutter 生产代码。
- 不直接搬用营销网站的满屏渐变、视差、3D、粒子或重度玻璃效果。
- 不通过“失败、违规、吃错、超标”等语言制造羞耻感。

## 2. 信息架构与关键页面

### 2.1 共享领域模型

```text

└── Day（日期）

    │   ├── FoodItem（食物项目）
    │   ├── InputSource（输入来源）
```

## 3. 核心流程与状态契约

### 3.1 核心记录闭环

```text
登录/注册
→ 今日饮食
→ 拍照 / 相簿 / 描述 / 手动 / 常用食物
→ AI 分析
→ AI 草稿审核
→ 编辑食物、份量、单位和营养值
→ 用户确认并储存
→ 已储存餐点
→ 今日反馈 / 趋势
```

所有输入方式都进入同一套餐点草稿模型；条码与营养标示（若功能已提供）也必须先进入可编辑确认，不可扫描后直接保存。

### 3.2 统一状态模型

最终冻结为以下共享状态。界面使用繁体中文文案，内部实现可用英文枚举：

```text
idle                 尚未开始
input                输入中
captured             已接收输入
uploading            上传中
analyzing            AI 分析中
review               待确认
review-unsaved       有未储存修改
saving               储存中
saved                已储存
offline              目前离线
pending-sync         待同步
error                操作未完成
permission-required  需要授权
permission-denied    尚未授权
syncing              同步中
sync-failed          同步未完成
empty                尚无资料
conflict             其他装置已有更新
```

**语义边界：**

- “AI 分析完成”不等于“餐点已储存”。
- `review` / `review-unsaved` 仍是草稿；只有用户按下确认并储存后才进入 `saving`。
- “本机保留”“账号已储存”“已同步”必须分开表达。
- 保存失败必须保留原始相片/文字、AI 草稿和用户修改。
- 离线状态不得伪装为服务器已储存；冲突不得静默覆盖任一版本。
- Health Connect 的 `permission-denied` 不影响 P0 饮食记录。

### 3.3 状态中心

Web 可放在侧栏底部/顶部辅助区，Android 放在饮食页待处理入口和顶部状态入口。按用户下一步分组：

```text
需要你处理：待确认草稿、储存未完成、尚未授权、冲突
处理中：AI 分析中、储存中、健康同步中
稍后重试：待同步、同步未完成、AI 分析失败
已完成：最近储存的餐点
```

每项显示：对象名称、所属日期、当前状态、最后更新时间、下一步 CTA。不可只用 Toast/SnackBar 承载长任务或关键错误。

### 3.4 Health Connect 边界

- Android：发起系统授权、说明实际数据类型、处理允许/部分允许/拒绝/撤销、执行同步。
- Web：展示同步结果、数据来源、最后更新时间和过期状态；不伪造 Web 直接授权。
- 用户拒绝 Health Connect 后仍可完整记录饮食。
- 必须区分：尚未授权、已授权但无数据、数据过期、部分同步、同步失败。
- 数据类型、读写方向、历史回填范围和同步频率仍需产品确认。

## 5. 组件规范

### Button

- `Primary`：拍照记录、记录饮食、确认并储存。
- `Secondary`：手动记录、查看详情。
- `Outline`：编辑、替换、取消。
- `Ghost`：关闭、撤销、稍后处理。
- `Destructive`：删除餐点、删除账号、清除数据。
- `IconOnly`：相机、编辑、关闭、更多；必须有 tooltip/无障碍名称。

状态：default、hover（仅 Web）、pressed、focused、disabled、loading、success、error。Loading 保留按钮文字；成功是短暂反馈后回到稳定状态；错误必须提供重试或替代路径。

### Input / AI Field

每个字段有 label、单位、必填性、范围和错误关联。AI 预填使用轻 `brand.soft` + “AI 估算”；用户修改显示“已由你修改”，不是错误；焦点有 3px focus ring；保存失败保留值。

### Card

- `Default`：中性表面 + 细边框。
- `HeroSummary`：深炭/深橄榄锚点，用于今日摘要。
- `Macro`：中性表面 + 单一宏量色。
- `AIDraft`：轻品牌底色 + AI 估算/待确认标签。
- `Empty`：说明 + 唯一主动作。
- `Error`：局部使用 danger，不整页染红。

### Chip / Badge

用于宏量、状态、AI、筛选；最小高度约 32px。Chip 不是主要提交按钮。宏量色不表达好坏。

### Navigation

Web active 使用 amber/olive surface；Android selected 使用 Material 3 indicator + brand 色。导航不使用 protein/fat/carbs 颜色，以免把数据语义和页面语义混淆。

### Toast / Snackbar

只用于低风险成功或补充提示，如“餐点已储存”“同步完成”。AI 未确认、保存失败、权限拒绝和关键错误必须在页面或状态中心持久呈现。

## 6. 平台与响应式规范

### Web 桌面（建议 ≥1280px）

- 左侧持久导航；主工作区 + 可选辅助面板。
- 今日页支持概览、餐点列表、饮水/建议/同步并行查看。
- AI 草稿采用图片/来源 + 编辑区双栏。
- 食物支持搜索、筛选、表格/列表、批量管理和详情抽屉。
- 支持 hover、键盘焦点、URL 日期/筛选、`Ctrl/Cmd+K` 搜索、`N` 新增（输入框聚焦时不触发）、`Esc` 关闭/处理未保存。
- 关键操作不依赖 hover；固定层不可遮挡保存动作。

### Web 平板（768–1279px）

- 折叠侧栏或紧凑导航；单栏为默认。
- 辅助面板转抽屉或下移。
- AI 双栏转上下单栏，不允许横向溢出。
- 触控场景仍按 48px 目标设计，不依赖 hover。

### Android 手机（建议 <768px）

- 单列 + 安全区内的「飲食 / 健康 / 設定」底部导航。
- 记录饮食是饮食页主行动；食物为上下文入口。
- 短任务使用 Bottom Sheet；复杂 AI 审核使用全屏页；固定确认栏避让键盘、手势区、刘海和底部导航。
- 使用系统相机、相簿、权限和返回手势；任何关键手势都有可见按钮替代。
- 支持下拉刷新、Sheet 上滑展开/下滑关闭、日期横滑、图片缩放和列表长按，但核心流程不依赖隐藏手势。
- 不把 Web 三栏、表格或玻璃背景缩小后直接复制到手机。

## 7. 动效、状态与无障碍

### 动效

- Hover/focus：100–160ms；pressed：80–120ms；状态：160–200ms；Dialog：180–220ms；Sheet/Drawer：220–320ms；图表/进度：240–400ms。
- 进入使用 fade + 4–8px 位移；AI 用阶段性文字 + 轻骨架/脉冲，不用无限 spinner 作为唯一说明；保存成功可短暂勾选。
- Web 环境光为可选装饰：低透明度、28–36s、仅背景；Android 默认静态暖表面，不使用全局动态 glass。
- 不引入 3D、粒子、shader、鼠标追踪、持续视差或强色散。
- `prefers-reduced-motion` 和 Flutter 系统减弱动画下，关闭位移、缩放、抖动、彩虹边框和循环动画，保留文字状态。

### 空、载入、错误、离线、同步

| 状态 | 标准文案/行为 |
|---|---|
| 今日空 | 今天还没有饮食纪录；主 CTA：记录饮食 |
| AI 处理中 | 正在分析这张相片…；可离开，状态进入状态中心 |
| AI 完成 | AI 分析完成，尚未储存；请确认内容后再储存 |
| 保存中 | 正在储存餐点…；禁重复提交 |
| 保存失败 | 储存未完成，草稿仍保留；重试储存 |
| 离线 | 目前离线；显示缓存时间，不伪装实时 |
| 待同步 | 草稿已在此装置保留，尚未同步 |
| 同步失败 | 同步未完成；资料仍保留，可重试 |
| 未授权 | 尚未授权；说明用途、提供前往设置/稍后处理 |
| 无数据 | 尚无资料；区分未授权和已授权无数据 |
| 过期 | 资料可能已过期；显示最后更新时间 |
| 无结果 | 找不到“{关键词}”；检查关键词、手动新增、AI 描述或条码/营养标示 |

### 无障碍门槛

- 正文对比度至少 4.5:1，大字至少 3:1；所有状态不依赖颜色。
- Web 全流程可用键盘完成，焦点可见；Dialog/Drawer 焦点进入、循环、关闭后回触发元素。
- 路由切换后焦点进入新页面标题；表单错误聚焦第一个错误字段并提供具体修复方法。
- 屏幕阅读器/TalkBack 能读出页面标题、字段、单位、AI 估算、用户修改、保存/分析/同步状态、按钮语义和图片替代描述。
- Android 和触控 Web 交互目标至少 48×48px；删除与编辑不能紧贴。
- 文字放大 1.3–1.5x 时不截断关键 CTA、状态和单位。
- 相片替代文字不得把 AI 不确定结果写成事实。
- 重要错误不可只放 Toast/SnackBar。

## 8. 内容与文案规范

### 8.1 语气

使用台湾繁体中文、亲切专业、短而具体。描述记录，不评价人；先说明发生了什么，再给下一步；错误先说明资料是否保留，再提供修复动作。使用“你”，保留 AI、Web、Android、Health Connect、Google 等正式名称。

### 8.2 核心词汇

统一使用：饮食纪录、餐点、食物项目、AI 分析草稿、AI 估算、AI 信心度、已由你修改、已储存、待同步、我的食物、健康资料、状态中心、相片、营养标示、饮水。

避免混用：饮食日记/饮食资料、食材/食物项目、AI 结果/已完成纪录、置信度/正确率、保存/储存、图片/相片、添加/新增。产品正式 UI 以“储存”为统一台湾用语。

### 8.3 CTA

- `记录饮食`、`拍照记录`、`从相簿选取`、`手动记录`
- `确认并储存`、`编辑内容`、`重新分析`、`改用手动记录`
- `重试储存`、`立即同步`、`前往设置`、`稍后处理`
- `新增食物`、`编辑餐点`、`删除餐点`、`返回今天的饮食`

避免模糊的“开始、完成、送出、好的、回首页”。

### 8.4 AI 文案

- 分析中：`正在分析这张相片…`
- 结果：`AI 已完成初步估算。请检查食物与份量，再储存这份纪录。`
- 标签：`AI 估算・待确认`
- 高/中/低信心度必须配说明，不显示未经模型团队确认的精确百分比。
- 无法辨识：`目前无法辨识这张相片中的食物。可以重新拍摄，或改用手动记录。`
- 修改后：`已由你修改；储存时会以你输入的内容为准。`
- 健康边界：`这些内容是个人纪录与趋势整理，不是医疗诊断或治疗建议。`
- 过敏边界：`AI 无法确认食物是否含有过敏原。请以食品包装标示或专业建议为准。`

### 8.5 健康反馈

使用“目前进度”“与目标的差距”“记录中”“约”，避免默认使用“超标、不及格、达标失败”。示例：

- `今天已记录 3 个餐点，热量约 1,520 kcal。`
- `依你设定的今日目标，目前记录为 80 / 120 g。`
- `目前有 3 笔纪录。想更完整回顾今天，可以继续记录下一餐。`
- `过去 7 天的记录中，蛋白质平均约为 85 g。`

### 8.6 单位与日期

- `热量 520 kcal`、`蛋白质 28 g`、`碳水化合物 65 g`、`脂肪 18 g`、`饮水 500 mL`、`体重 62.4 kg`。
- AI 估算用“约”或范围，不用过多小数制造精确假象。
- 完整日期：`2025 年 3 月 8 日（週六）`；短日期：`3/8（週六）`；时间：`12:30`；期间：`过去 7 天`、`本週`。
- 跨平台与数据导出须统一日期、时区和单位；最终地区/单位政策待确认。

## 9. 设计冲突处理与待确认事项

### 本次冻结的设计决策

1. Web 保留四个领域导航：饮食、健康、食物、设置；桌面优先侧栏。
2. Android 保留三项底部导航：饮食、健康、设置；食物作为上下文入口。
3. AI 结果统一命名为草稿/估算；确认并储存是正式记录边界。
4. “储存”“待同步”“已同步”三者不混用；保存失败保留草稿。
5. Web 可有限使用 glass/环境光；Android 以 Material surface 为主。
6. 默认摘要优先、详情渐进披露，不建立割裂的两套用户模式。
7. 使用台湾繁体中文作为本阶段基准内容语言；产品正式用语统一“储存”。

### 保留为产品决策的问题

1. 目标地区、语言、繁简体范围、时区与单位系统。
2. Web 与 Android 是否都支持深色模式及其上线范围。
3. Logo、正式品牌图形、字体资产与 Android 是否内置 Noto Sans TC。
4. Android 是否允许离线创建/确认餐点；草稿保存期限、加密和跨设备恢复。
5. 本机储存、账号储存、已同步的正式定义，以及多设备冲突规则。
6. AI 信心度算法、分级门槛、是否逐项显示；营养值能否直接编辑或只能改份量。
7. 相片是否保存、保存多久、是否发送第三方 AI 服务及删除/导出方式。
8. Health Connect 读取的数据类型、读写方向、同步频率和历史回填范围。
9. 目标来源（用户输入、系统模板或建议）和每日反馈触发方式。
10. Google 是登录方式、附加绑定，还是两者都支持。
11. 条码/营养标示功能何时上线；未上线前不得显示正式 CTA。
12. 我的食物包括哪些来源，以及删除/封存对历史餐点的影响。
13. 是否支持特殊人群、过敏原、孕期、儿童和饮食失调风险提示。
14. 是否需要分析/同步完成通知，最低 Android 版本和设备范围。

## 10. 实施优先级与风险

### P0：共享基础和核心闭环

- 冻结 semantic color、字体层级、间距、圆角、边框、焦点、触控和状态命名。
- 建立今日工作台、记录入口、AI 草稿审核、确认储存、餐点详情和空/载入/错误状态。
- 统一草稿/用户修改/正式记录/待同步的视觉和文案边界。
- Web 与 Android 分别完成侧栏/底部导航、键盘/触控、安全区/返回和 reduced-motion 规则。

### P1：长期使用能力

- 营养趋势、饮水、健康数据、Health Connect 状态与恢复。
- 我的食物、最近/常用/收藏、食物搜索和无结果替代路径。
- 状态中心、缓存优先、长任务恢复、保存失败重试。

### P2：增强与高风险设置

- 条码、营养标示、完整个人食物库。
- AI 高级设置、Google 绑定、隐私/图片管理、版本更新。
- 空状态插画、有限环境光、SVG 状态动画等非关键 polish。

### 主要风险

- **AI 信任**：过强的“完成/高置信”视觉会让用户跳过确认；必须保留估算、编辑和保存边界。
- **健康焦虑**：红色、目标评分和评判性文案可能伤害持续使用；使用中性、行动导向语言。
- **离线/同步**：旧缓存、重复保存和多设备编辑可能造成数据误解；需幂等、可恢复、可冲突解决。
- **敏感资料**：相片、饮食、体重、Health Connect 数据需明确权限、保存和删除策略；日志不得记录原始敏感内容。
- **平台适配**：玻璃/模糊、键盘、Bottom Sheet 和固定底部栏可能造成性能或遮挡；必须真机和响应式测试。
- **本地化**：繁体中文字宽、单位、日期和长食物名称可能破坏布局；需要大字与多设备测试。

## 11. 验收清单与下一步

### P0 用户任务

- 新用户能完成：登录 → 今日 → 拍照/手动 → AI 草稿 → 编辑 → 确认并储存。
- 用户能理解 AI 分析完成不等于餐点已储存。
- 保存失败、网络中断或离开页面后，原始输入与编辑内容仍可恢复。
- 拒绝 Health Connect 后仍可完成饮食记录。
- Web 与 Android 对同一餐点使用相同字段和状态语义。

### 平台与无障碍

- Web 桌面/平板没有横向溢出，侧栏、双栏和抽屉在合理断点切换。
- Android 小屏、手势导航、刘海、软键盘和系统大字下，主行动与固定栏不遮挡。
- 键盘、TalkBack/屏幕阅读器、焦点、对比度、触控目标和 reduced-motion 验收通过。
- AI、保存、同步、权限、空状态、错误状态都有持久且可行动的反馈。

### 不在本阶段生成

本阶段没有生成 HTML 原型，也没有修改 Web/Flutter 生产代码。下一步应先确认第 9 节产品决策，再选择“关键页面原型”或“完整原型”。
