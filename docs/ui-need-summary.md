# UI 需求摘要

- **执行模式**：深度模式
- **产品定位**：AI Food Diary 是一款 Flutter Android 饮食记录应用，帮助用户用拍照、描述或手动输入低负担记录餐点，并在 AI 估算后由用户确认、储存与回顾。
- **目标平台**：仅 Android 手机原生体验；不设计 Web、平板或桌面布局。
- **目标用户**：大众日常健康用户为主；通过摘要优先、详情渐进展开兼顾进阶营养用户。
- **核心功能（P0/P1/P2）**：
  - **P0**：今日饮食、日期切换、拍照/相簿/文字描述/手动记录、AI 分析草稿、编辑与确认并储存、餐点列表与详情、空/载入/错误/离线反馈。
  - **P1**：健康概览与 Health Connect 同步、饮水、每日反馈、历史/趋势、我的食物与快速加入、后台分析恢复与状态中心。
  - **P2**：条码与营养标示、Google 绑定、AI 设置、隐私/数据管理、更新与管理员入口等高级设置。
- **关键页面/流程**：登录/注册 → 今日饮食 → 新增餐点来源选择 → 原生相机/相簿/描述/手动表单 → AI 分析中 → AI 草稿审核 Bottom Sheet/全屏审核页 → 确认并储存 → 餐点详情；健康；我的食物；设置；权限、离线、同步与失败恢复。
- **移动端约束**：触控优先、至少 48×48dp 触控目标、Material 3、三项底部导航「飲食 / 健康 / 設定」、安全区、系统返回、手势导航、Bottom Sheet、键盘避让、单手可达、弱网/离线与可恢复任务、TalkBack、动态字体、深色模式和减少动画。
- **共享基础**：遵循 `docs/ui-design-system-shared.md` 的品牌色、语义状态、繁体中文词汇、AI 草稿边界与跨平台对象语义；保留产品身份但不缩小 Web 布局。
- **现有 App 事实**：`mobile/` 为 Flutter Android 应用；已有 `DashboardScreen` 三项底部导航、缓存优先启动、后台 AI 分析、Health Connect、常用食物、条码/营养标示入口、深浅主题与若干 Maestro 流程。
- **风格方向**：温暖、可信、非评判式；以暖琥珀/陶土/橄榄辅助色和中性表面承载食物温度，Android 以 Material surface 为主，不使用重玻璃、强渐变或装饰性 3D。
- **本轮范围**：生成 Mobile-App-specific UI/UX specification；只写 `docs/` 与任务归档，不修改 `mobile/`、`src/`、依赖或生产配置。
- **待确认问题**：离线创建与草稿保存期限；本机/账号/同步边界与冲突处理；Health Connect 数据类型与权限范围；AI 信心度与营养编辑规则；目标地区、单位、深色模式上线范围；相片保存、删除与隐私策略。
