# UI 需求分析报告

> 本报告仅针对 Android 手机原生 App。报告说明使用简体中文；引号内 UI 文案统一采用台湾繁体中文。

## 一、产品定位

- **一句话定义**：AI Food Diary 是一款以拍照、描述或手动输入为入口，将餐点整理成可编辑 AI 草稿，并由用户确认储存的 Android 饮食记录 App。
- **类型**：健康工具 / AI 辅助记录工具
- **阶段**：迭代优化；重点重构移动端信息架构与核心记录闭环，不修改生产代码
- **移动端价值主张**：在餐厅、家中、办公室等场景下，用手机快速完成一餐记录；AI 负责减少输入，不替用户做最终判断；AI 估算必须经过用户检查、修改与「確認並儲存」；无法拍照、AI 失败或网络中断时，仍提供清晰的手动替代路径；以摘要优先服务大众用户，以渐进展开满足营养进阶用户。
- **非目标**：不提供医疗诊断、治疗或绝对准确的营养结论；不将未确认 AI 结果直接写入正式记录；不要求 Health Connect 授权后才能记录饮食；不把 Web 的三栏、玻璃效果或营销布局缩小到手机。

## 二、目标用户

- **主要用户**：大众日常健康用户。希望低负担了解今天吃了什么，并获得温和、可行动的反馈；不应被复杂营养字段、AI 术语或失败流程阻挡。
- **次要用户**：健身与营养进阶用户。关注热量、蛋白质、脂肪、碳水、份量、目标差距、体重、活动消耗与历史趋势，需要更精确的编辑和数据来源。

### Persona / JTBD

| 用户 | 主要任务 |
|---|---|
| 大众用户 | “当我刚吃完一餐时，我想用最少步骤记录它，并知道记录是否真的储存完成。” |
| 大众用户 | “当 AI 识别不准确时，我想直接修改或改用手动记录，而不是重新开始。” |
| 进阶用户 | “当我需要控制营养摄取时，我想查看份量、单位、三大营养素与数据来源。” |
| 进阶用户 | “当我重复吃相同食物时，我想从「我的食物」快速带入并调整份量。” |

**共存原则**：不建立割裂的“简单模式 / 专业模式”；默认展示摘要，详细营养、目标、来源和历史通过展开或进入详情页提供。

## 三、核心功能（按优先级）

### P0：核心记录闭环

1. 账户进入与会话恢复。
2. 今日饮食首页：日期、今日摘要、餐点列表、记录入口、待处理任务。
3. 新增餐点来源选择：`拍照记录`、`從相簿選取`、`文字描述`、`手動記錄`。
4. 原生相机与相簿输入：最多 5 张照片，处理权限、读取、上传和图片失败。
5. AI 分析草稿：食物项目、份量、单位、热量、三大营养素，标记 `AI 估算・待確認`。
6. 草稿编辑：修改、删除、新增食物项目，区分 AI 估算与用户修改。
7. `確認並儲存`：区分分析完成和餐点已储存，防重复提交。
8. 餐点列表与详情：餐别、时间、照片、食物项目、营养摘要和来源。
9. 编辑与删除餐点：删除二次确认；编辑失败保留原内容。
10. 关键离线、错误、空状态：不能只用 SnackBar；错误必须可理解、可恢复。
11. 待处理入口：找回分析中、分析失败、储存未完成与待同步任务。

### P1：持续使用能力

- 健康概览与 Health Connect：授权、同步、部分授权、无数据、过期与失败。
- 饮水记录与目标。
- 历史与趋势。
- 每日反馈：事实摘要、趋势、下一步建议，避免羞辱。
- 我的食物：搜索、最近、常用、编辑、封存、还原、快速加入。
- 后台任务恢复与状态中心。
- 同步记录：最后时间、范围、成功数量、失败原因、重试。

### P2：增强与高风险设置

条码扫描、营养标示识别、品牌搜寻、Google 绑定、AI 设置、隐私/照片/数据删除导出、更新、管理员入口，以及特殊饮食/过敏原/孕期/儿童风险提示（需确认后设计）。

## 四、关键页面/流程

> 以下为 Android 逻辑路由，不是 Web URL；不应直接复制 Web 页面结构。

### 启动与账户

- `Splash / Session Gate`【P0】：只负责启动、会话检查与任务恢复，不长时间阻塞。
- `登入`【P0】：邮箱、密码、人机验证、Google 登录、错误恢复。
- `建立帳號`【P0】：注册字段与失败恢复。

### 饮食 Tab

- `飲食・今日`【P0】：日期切换、今日摘要、待处理、主记录行动、饮水、餐点列表。
- `記錄方式選擇 Sheet`【P0】：只承载拍照、相簿、描述、手动、我的食物。
- `原生相機 / 相簿流程`【P0】：系统能力、权限、取消、图片限制与读取失败。
- `文字描述頁`【P0】：键盘、字数、清除、提交。
- `手動記錄頁`【P0】：必要字段优先，营养字段渐进披露，数值键盘和字段错误。
- `我的食物選擇器`【P1】：记录流程中的上下文入口。
- `AI 分析狀態頁 / 狀態區塊`【P0】：上传、分析阶段、离开后找回。
- `AI 草稿審核頁`【P0】：全屏；多项目编辑；底部固定 `確認並儲存`，避让键盘和手势区。
- `餐點詳情頁`【P0】：正式记录、来源、AI 估算、用户修改、照片、营养值、编辑。
- `餐點編輯頁`【P0】：修改与未储存保护。
- `歷史 / 日期檢視頁`【P1】：过去日期与趋势，不堆入今日长页面。
- `每日回饋頁或 Sheet`【P1】：可关闭、可再次进入、不阻塞首次记录。
- `狀態中心`【P1；关键待处理入口为 P0】：按需要处理、处理中、稍后重试、已完成组织任务。

### 健康 Tab

`健康概覽`、`Health Connect 授权说明`、`同步处理中/结果`、`指标详情/历史 Sheet`、`飲水页或饮食内入口`，分别处理授权、无数据、过期、失败和重试。

### 设置 Tab

`設定首頁`、`個人資料與身體資料`、`我的食物管理`、`AI 設定`、`Google 綁定`、`隱私與資料`、`更新 / 關於`、`管理員設定`。

### P2 记录增强

`條碼掃描頁`、`營養標示拍攝頁`、`品牌營養搜尋頁` 在产品确认前不占据 P0 主路径。

## 五、Android 约束

- Flutter Android 手机；仅移动端。
- 底部三项 `飲食 / 健康 / 設定`，使用 Material 3 NavigationBar。
- 最小触控目标 48×48dp；图标按钮有无障碍名称。
- 处理状态栏、刘海、底部导航栏、手势区和键盘 Insets。
- 记录主行动位于单手可达区域，不被底部导航或键盘遮挡。
- Bottom Sheet 只用于来源选择、短筛选、短确认、简单编辑；长表单和复杂审核使用全屏。
- 系统 Back：输入中提示保留；分析中允许离开并恢复；审核未储存提示保留/放弃/继续；Sheet 支持返回、关闭、拖曳。
- 手势有可见按钮替代；支持下拉刷新、日期切换、图片浏览但不依赖隐藏手势。
- 字体放大 1.3–1.5 倍时 CTA、单位、状态、错误不截断。
- TalkBack 读出页面标题、字段、单位、AI 估算、用户修改、状态和下一步。
- 状态不能只靠颜色；支持系统深色模式与 Reduced Motion。
- 相片、饮食、体重、健康资料视为敏感数据。

## 六、统一状态与边界

| 状态 | UI 含义 | 必须动作 |
|---|---|---|
| `idle` | 尚未开始 | 记录入口 |
| `input` | 正在输入 | 继续、清除、返回保留 |
| `captured` | 输入已在本机接收 | 预览、编辑、分析 |
| `uploading` | 正在上传 | 防重复提交、必要时取消 |
| `analyzing` | AI 处理中 | 阶段说明；允许离开并恢复 |
| `review` | AI 草稿完成，尚未储存 | 查看、修改、确认 |
| `review-unsaved` | 修改未储存 | 保留、继续审核 |
| `saving` | 正在储存正式记录 | 禁重复提交 |
| `saved` | 账号储存完成 | 详情、返回今日 |
| `offline` | 无网络 | 显示缓存时间，不伪装实时 |
| `pending-sync` | 本机保留未同步 | 查看、重试、稍后 |
| `error` | 操作未完成 | 保留资料、重试、替代 |
| `permission-required` | 尚未请求权限 | 说明用途、请求、稍后 |
| `permission-denied` | 拒绝/系统阻止 | 前往设置；继续其他功能 |
| `syncing` | 同步中 | 显示范围/进度，防重复 |
| `sync-failed` | 同步未完成 | 原因、重试、日志 |
| `empty` | 没有资料 | 原因与唯一主 CTA |
| `conflict` | 版本不同 | 比较、保留/采用/合并 |

强制边界：AI 分析完成不等于储存；本机、账号、同步分开表达；保存失败保留全部编辑；离线不能显示服务器已储存；冲突不静默覆盖；Health Connect 拒绝不阻塞饮食记录；关键错误不只放 SnackBar。

## 七、现有能力复用边界

### 可复用

`AppTheme` 的 Material 3/主题/语义色、三 Tab NavigationBar、Splash/登录/注册、缓存优先、相机/相簿/图片限制、三种输入、WorkManager 后台分析、餐点列表/编辑/删除、Health Connect、饮水、我的食物、条码、营养标示、Google、更新等服务能力。

### 不能直接沿用

- Dashboard 单长滚动承载所有内容。
- 复杂 AI 审核 Bottom Sheet。
- AI 状态主要依赖 SnackBar/局部 Banner。
- 自动昨日总结 Dialog 直接打断首次使用。
- 小屏固定三列健康指标网格。
- 只用长按触发批量食物操作。
- 负面 AI 评级文案。
- 一次暴露所有手动、条码、营养标示、品牌与营养字段。
- 简化的 AI `idle/running/done/error` 代替完整产品状态。
- 现有 Maestro 基础流程代替离线/权限/TalkBack/大字/恢复验收。

## 八、验收场景与成功标准

1. 新用户完成登录 → 今日 → 记录方式 → AI 草稿 → 修改 → `確認並儲存` → 餐点详情。
2. 相机拒绝、不想拍照或 AI 失败时仍能进入 `手動記錄`。
3. AI 结果明确为 `AI 估算・待確認`，确认前不显示为正式餐点。
4. AI 失败保留相片/描述，可重试、手动或稍后处理。
5. 保存失败保留编辑值，重试不重复生成。
6. 离线可打开缓存，显示 `目前離線` 和缓存时间。
7. 后台分析在切换 App、锁屏或重启后可恢复。
8. 拒绝 Health Connect 后仍可记录、储存饮食。
9. 未授权、已授权无数据、过期、同步失败各自可理解。
10. 冲突可查看版本并选择，不能静默丢失。
11. 键盘弹出 CTA 仍可见；返回不无提示丢失。
12. 大字与 TalkBack 下状态、单位、动作可访问。
13. 深色与 Reduced Motion 下信息仍可辨识。
14. 无餐点、无健康资料、无食物、无搜索结果均可继续。

## 九、待确认问题

- 离线是否允许确认/储存正式餐点，草稿保留多久。
- “本机保留 / 账号储存 / 已同步”正式定义。
- 多设备冲突选择、合并或保留副本。
- AI 信心度展示、营养值编辑规则、当前评级是否移除/中性化。
- 相片保存/删除/导出与第三方 AI 发送。
- Health Connect 读取/写回数据、历史范围、频率。
- 每日反馈触发与通知默认策略。
- 台湾单位是否固定；深色模式上线范围；Google 登录/绑定关系。
- 条码/营养标示正式上线时机；我的食物删除语义；特殊人群提示。
- 最低 Android 版本与设备范围。

## 十、下游统一约束

- **form**：首屏少字段，营养渐进披露，数值键盘、单位、错误与未储存保护。
- **visual**：暖琥珀、陶土、橄榄、Material 3 surface；不复制 Web 玻璃/三栏/强渐变；状态不只靠颜色。
- **IA**：固定三 Tab；不新增食物 Tab；今日、状态中心、待处理是核心。
- **interaction**：48dp；短任务 Sheet、复杂审核全屏；安全区、键盘、Back、返回手势、后台恢复。
- **content**：台湾繁体中文；`餐點`、`飲食紀錄`、`AI 估算`、`確認並儲存`、`待同步`、`我的食物`；避免评判语言。
- **all**：覆盖完整状态契约及其边界。
