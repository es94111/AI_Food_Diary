# UI 形态分析报告

> 本报告只针对 Flutter Android 手机原生体验；不设计 Web、平板或桌面布局。

## 一、形态总览

- 直向优先，支持手机横向但不切换成平板三栏。
- 整体布局：底部三 Tab + 单栏工作区；主要任务使用全屏页，短任务才使用 Sheet。
- Material 3 `NavigationBar`：`飲食`、`健康`、`設定`。
- 页面层级：Splash/Session Gate → 登录流程 → 三 Tab Root Shell → 全屏子页 → Modal/Draggable Bottom Sheet 或 Dialog → Android 系统页/外部服务页。
- NavigationBar 只存在于三 Root Tab；全屏输入、AI 审核、详情、设置子页隐藏底部导航。
- 不新增「食物」第四 Tab；我的食物从设置或记录流程进入。

## 三、核心页面布局

### 1. 饮食・今日工作台

**形态**：Root Tab，单栏纵向工作台。

**推荐顺序**：
1. 日期与资料新鲜度。
2. 今日热量摘要与可展开营养详情。
3. 明确主行动「記錄餐點」。
4. AI 分析中、待审查、待同步等持久状态 Banner。
5. 今日餐点列表。
6. 历史与每日回馈入口。

当前 `DashboardScreen` 将日期、热量、净热量、饮水、完整新增餐点、餐点列表与总结堆成一条长滚动；建议把输入表单、复杂 AI 审核、详细健康与每日回馈移出首页。首页应回答「今天吃了什么、是否已储存、下一步是什么」，而不是承载所有功能。

- 点击日期 → 日期选择或历史页。
- 点击记录餐点 → 记录方式 Sheet。
- 点击餐点 → 详情页。
- 点击待处理 Banner → 状态中心/草稿审核。
- 下拉刷新 → 页面内更新状态。
- 主行动固定在底部导航上方安全区内，或用可避让安全区的 Floating/Bottom action。

状态：今日为空时显示「今天還沒有餐點紀錄」+「記錄第一餐」；缓存显示上次更新时间；离线显示「目前離線」并明确本机/服务器边界；错误使用页面内 Error Banner + 重试，不仅靠 SnackBar。

### 2. 记录方式 Sheet 与原生相机/相簿

**形态**：Modal/Draggable Bottom Sheet + Android 系统页。

Sheet 标题「怎麼記錄這餐？」；四个同等可见选项：`拍照`、`從相簿選擇`、`文字描述`、`手動輸入`。支持拖曳、关闭、系统返回、底部安全区。

照片输入：最多 5 张；显示数量与剩余槽位；每张缩图都有移除；拍照后回到照片输入页，明确显示「開始 AI 分析」，避免无提示直接上传。处理上限、图片大于 6MB、无法读取、权限拒绝都要页面内说明和替代路径。

### 3. 文字描述页

**形态**：全屏单栏表单，底部固定 CTA。

字段：餐别、多行描述、字数限制、AI 估算说明。示例：
- 标题：「描述這餐」
- Placeholder：「例如：午餐吃了一碗滷肉飯、一顆滷蛋和一杯無糖豆漿。」
- 说明：「AI 會依照你的描述建立可編輯草稿，數值需要由你確認。」

键盘出现时自动滚动当前字段；有内容 Back 时提示「保留這份描述／放棄／繼續編輯」。空白送出提示「請先描述你吃了什麼。」；AI 失败保留原文，提供重试与手动替代。

### 4. 手动记录页与我的食物选择器

**形态**：全屏手动表单 + 全屏搜索选择页。

默认只显示食物名称和份量；营养字段「展开營養資料」后显示热量、蛋白质、脂肪、碳水。各字段标明单位，单栏排列，避免小屏三列。底部固定主 CTA。

我的食物选择器使用全屏列表：顶部搜索；筛选/排序使用短 Filter Sheet；点食物后返回手动页带入。条码、营养标示、品牌搜寻放入「更多資料來源」次级区，不干扰 P0。字段错误贴近字段展示；保存失败保留全部内容。

### 5. AI 状态与草稿审核

**AI 状态**：全屏状态页 + 跨页持久 Banner。上传与分析分开表达：
- 「正在上傳照片…」
- 「AI 正在分析這餐…」
- 「分析完成，尚未儲存。」
- 「分析失敗，原始內容已保留。」

分析中允许返回今日页，状态中心可恢复；完成后「查看草稿」。离线显示尚未上传，待同步显示本机保留。

**AI 草稿审核**：复杂多项目内容使用全屏单栏审核，不使用长 Sheet。

- 顶部：「AI 估算草稿・尚未儲存」。
- 内容：照片/描述上下文、食物项目、可展开营养字段、新增/删除食物、来源说明。
- 默认显示名称、份量、热量；展开显示三大营养素与来源。
- 重新估算必须由用户主动触发，不可覆盖手动修改。
- 底部固定「確認並儲存」；储存中锁定，避免重复提交。
- Back 未储存时提示保留、放弃或继续。
- 成功进入餐点详情，不阻塞成功 Dialog；失败显示「餐點尚未儲存，內容已保留」+ 重试。

不以「較推薦／普通／建議少吃」作为主要评价，避免与非评判定位冲突。

### 6. 餐点详情、编辑、历史与回馈

详情全屏单栏：餐别/时间/储存状态 → 照片 → 食物摘要 → 营养总结 → 来源与同步 → 编辑/删除。编辑使用全屏表单，底部固定「儲存變更」。删除使用短 Dialog；照片失败不影响营养查看；离线不宣称服务器已更新。

历史使用全屏日期列表与单日餐点，趋势/每日回馈独立进入详情；每日回馈不再自动阻塞 Dialog，改为可召回的非阻塞入口。历史/回馈空、载入、生成失败都不能阻塞餐点查看。

### 7. 状态中心

全屏单栏，按「待處理／進行中／稍後重試／已完成」分组。每项提供查看、重试、返回来源、完成时间；没有任务显示「目前沒有待處理項目」。关键任务不能只放通知或 SnackBar。

### 8. 健康与同步

健康 Root Tab 使用单栏健康工作区，小屏不使用三列指标卡；小屏单列或两列列表，大屏手机最多两列，指标分组可展开。显示 Health Connect 连接状态、最后同步、今日活动、饮水、指标群组、手动同步与日志。

授权使用 App 全屏说明页 → Android 系统页；说明数据类别与用途；拒绝不阻塞饮食。部分授权明确缺少哪些资料。同步结果显示时间、数量、部分失败、营养确认、再次同步和日志；不过度依赖颜色。

指标历史使用单指标全屏详情，图表、摘要、历史列表依次排列；饮水可从摘要进入简单短表单或全屏详情。

### 9. 设置与我的食物

设置 Root Tab 使用分组列表，不把设置堆成一张卡片；账户、身体资料、我的食物、AI、Google、隐私、更新、管理员、登出各自进入全屏子页。

我的食物使用全屏列表、搜索、筛选、排序和明确「選取」模式；不依赖长按才可发现批量操作。封存不影响历史餐点，需在 UI 中说明。重复/相似食物用 Dialog 明确处理选项。

## 四、导航与容器边界

- Root Shell 三 Tab；切换 Tab 不清除各自状态，返回子页后回到原 Tab 与滚动位置。
- 全屏页使用 AppBar 返回和 Android Back；隐藏底部导航。
- Sheet 仅来源、短筛选、短确认、简单编辑；支持返回、关闭、拖曳、安全区。
- Dialog 仅删除、放弃、重复、短确认，不承载长表单、AI 审核、同步结果。
- 页面内 Tab/Segmented control 只用于同页互斥输入模式，如拍照/描述/手动，不替代 Root NavigationBar。
- 我的食物分类多时使用搜索 + Filter Sheet，不硬塞水平 Tab。

## 五、Android 手机尺寸规则

- ≤359dp：单栏；健康指标不三列；营养逐项/两列；CTA 短文案或可换行；照片可水平滑动。
- 360–411dp：单栏工作台和表单；健康最多两列，长文本可换行。
- 412–599dp：仍为手机单栏主流程；摘要/健康可两列；AI 审核不变桌面双栏。
- 短高度约 ≤640dp：固定 CTA 可见；次要说明折叠；键盘时自动滚动。
- 横向：不切换平板三栏，表单/审核仍单栏；导航栏仍在底部；图表/照片可横向滚动。
- 所有尺寸：至少 48×48dp；处理系统栏、刘海、手势区、键盘 Insets；字体 1.3–1.5 倍不截断标题、单位、CTA。

## 六、组件策略

推荐继续使用 Flutter Material 3 和现有 `app_theme.dart`，保留 `NavigationBar`、`FilledButton`、`OutlinedButton`、`TextField/Form`、`Card/ListTile`、`AlertDialog`、`showModalBottomSheet`、`LinearProgressIndicator`。不引入新 UI 套件，不用大量 Card 套 Card，不用长 Sheet 做 AI 审核，不用 SnackBar 传关键状态。

## 八、关键风险与验收

风险：全屏返回可能丢草稿；固定 CTA 被键盘/手势区遮挡；状态混淆；健康数据过密；长按批量不可发现；权限拒绝中断。

验收需覆盖：离线记录与恢复、相机/相簿拒绝、AI 分析中离开后恢复、AI 完成未储存、保存失败保留内容、Health Connect 部分授权、1.5 倍字体、TalkBack 焦点、重复提交与冲突。

本报告仅产出形态与布局规范，未修改生产代码。
