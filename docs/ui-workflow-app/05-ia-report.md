# UI 信息架构分析报告

> 范围：仅针对 Flutter Android 手机原生体验；不设计 Web、平板或桌面，不修改生产代码。

**证据标记**：`[事实]` 来自现有代码或上游文件；`[研究]` 来自外部来源；`[建议]` 为本报告决策；`[假设/待确认]` 为未冻结规则。

## 一、导航与用户心智模型

用户的主要心智模型不是「使用 AI 功能」，而是：

> 我想记录某一天的一餐 → 看看内容是否正确 → 确认是否真的储存 → 之后回顾自己的饮食与健康状态。

```text
User 用户
└── Day 日期
    ├── Meal 餐点
    │   ├── FoodItem 食物项目
    │   ├── InputSource 输入来源
    │   ├── AIDraft AI 草稿
    │   └── UserConfirmation 用户确认
    ├── DailyFeedback 每日回馈
    └── HealthSummary 健康摘要

StateTask 状态任务
├── AI 分析
├── 餐点储存
├── 离线待同步
├── Health Connect 同步
└── 冲突处理

HealthData 健康资料
└── Health Connect 权限、资料、更新时间、同步状态

SavedFood 我的食物
└── 可重复带入的食物模板，不等同于历史餐点
```

核心边界：`AI 分析完成 ≠ 餐点已储存`；`本机保留 ≠ 账号已储存 ≠ 已同步`。

### 主导航

- **飲食**：今日、记录餐点、餐点详情、历史、每日回馈、草稿与状态中心。
- **健康**：健康概览、Health Connect、健康指标、饮水、趋势与同步记录。
- **設定**：资料、我的食物、AI、Google、隐私、更新与管理员。

[研究] Android Navigation Bar 官方建议 3–5 个同等重要目的地；三项分别对应「我吃了什么」「我的健康资料」「应用与账号如何运作」。食物是记录上下文对象，不增加第四 Tab。

- 状态中心不是第四根导航，而是跨领域任务入口：从饮食页待处理卡、通知、冷启动恢复和健康页进入。
- 底部导航只存在于三 Root 页面；全屏输入、审核、详情、历史、健康详情、设置子页隐藏底部导航。
- 系统 Back、AppBar 返回和取消/关闭都必须可用；不能只依赖边缘滑动手势。
- 切换 Tab 不清除各自滚动位置和未完成状态。

## 二、现有结构与 IA 调整

- `[事实]` `mobile/lib/screens/dashboard_screen.dart` 已有三项 `NavigationBar`、`IndexedStack` 与三个 Tab。
- `[事实]` 当前 `_foodTab()` 将日期、热量、饮水、完整 `MealCaptureForm`、餐点列表和每日总结放在同一长页面。
- `[事实]` `meal_capture_form.dart` 同时承担拍照、描述、手动、我的食物、条码、营养标示、品牌搜寻和 AI 分析。
- `[建议]` 保留三 Root 导航，但拆出长任务与复杂对象，避免继续扩张 Dashboard 单页责任。

**今日页的新责任**：只回答「今天记录了什么、是否完成储存、下一步是什么」。完整输入、复杂审核、详细健康和每日回馈移出首页。输入从今日页一步进入，不会增加核心路径长度。

**不增加食物 Tab 的原因**：食物主要发生在记录流程；选取与管理是两个不同场景；三项根导航已对应稳定心智模型；增加第四项会削弱饮食作为主入口。需任务测试验证我的食物入口是否够易发现。

## 三、信息层级与关键页面

### Session Gate / 登录

第一层：会话恢复、进入应用或登录。第二层：登录、注册、重试。第三层：Google、错误和隐私说明。Session Gate 只负责恢复会话、缓存和后台任务，不长期阻塞今日页；失败保留输入并说明下一步。

### 飲食・今日

第一层：日期、资料新鲜度、今日摘要、主行动 `記錄餐點`。第二层：待确认、分析中、待同步、餐点列表、简短饮水状态。第三层：营养明细、来源、每日回馈、历史入口。

日期是上下文切换，不是额外根导航；每日/每週视图可保留为历史/趋势能力，今日默认单日。

### 记录方式 Sheet

第一层：`拍照記錄`、`從相簿選取`、`文字描述`、`手動記錄`。第二层：当前日期、默认餐别、取消。第三层：我的食物、条码、营养标示等增强来源。四个 P0 入口同等可发现；P2 不放第一层。

### 文字描述 / 手动记录

第一层：餐别、描述或食物名称、份量、继续。第二层：我的食物、增加项目、照片。第三层：热量、蛋白质、脂肪、碳水、条码、营养标示。手动默认名称、份量、单位；营养渐进展开；输入最终进入统一草稿流程。

### AI 分析状态

第一层：上传/分析/完成/失败阶段、原始内容是否保留。第二层：查看草稿、重试、改手动、稍后处理。第三层：任务时间、失败原因、同步诊断。分析中可离开，完成进入草稿审核；失败不只显示 SnackBar。

### AI 草稿审核

第一层：`AI 估算・待確認`、餐别、项目、份量、主要营养摘要、固定 `確認並儲存`。第二层：编辑、新增、删除、用户修改、来源。第三层：详细营养、信心度、重新分析、技术来源。复杂审核全屏；审核是草稿转正式餐点的唯一边界；储存失败保留全部。

### 餐点详情/编辑

第一层：餐别、日期时间、正式储存状态、热量与摘要。第二层：相片、项目、份量、宏量、编辑/删除。第三层：来源、AI 估算、用户修改、同步记录。编辑全屏；删除二次确认；离线编辑不能显示服务器已更新。

### 历史/回馈/趋势

第一层：日期或时间范围、餐点数量与摘要。第二层：单日餐点时间线、回馈入口、趋势入口。第三层：单一指标趋势、来源、筛选、详细数据。日期选择器、前后日期和回到今天优先；不用多个横向 Tab；回馈可召回，不阻塞今日。

### 状态中心

按下一步分组：
1. `待處理`：待确认草稿、储存未完成、权限、冲突。
2. `進行中`：AI 分析、储存、Health Connect 同步。
3. `稍後重試`：待同步、同步失败、分析失败。
4. `已完成`：最近储存、同步、处理任务。

状态中心是任务清单，不是技术日志；每项显示对象、日期、状态、更新时间和下一步 CTA。

### 健康/授权

第一层：Health Connect 状态、资料可用性、最后同步、健康摘要、饮水。第二层：活动、身体、睡眠、生命征象分组、同步和指标。第三层：权限范围、来源、日志、历史。

未授权、已授权无资料、过期、部分授权、同步失败必须分开。授权使用 App 说明页 → 系统页；拒绝后仍能用饮食。

### 设置/我的食物

设置首页只做分类：账户、资料、身体、我的食物、AI、Google、隐私、更新、管理员、登出。我的食物选取模式与管理模式分开；管理页搜索、最近、常用、筛选、排序、明确选取/多选模式，不只长按；封存不影响历史。

路由完成规则：

- 记录来源选择后进入所选输入页；相机取消不建立空任务。
- 输入送出进入分析状态；分析中 Back 回今日/状态中心，完成进入审核。
- 审核确认后进入餐点详情；返回需保留草稿或确认放弃。
- 详情从今日/历史/状态中心进入，返回原来源。
- 我的食物选取完成后回原手动表单并带入，不直接储存餐点。
- 子页完成后返回设置首页或原进入页；未保存设置返回需提示。

## 五、核心用户旅程

### 首次记录

`session.gate` → 登录/注册 → `app.diet.today` → 记录方式 → 相片/描述/手动 → 分析 → 草稿审核 → 餐点详情。重新打开 App 可从今日待确认任务或状态中心恢复。

### 快速拍照

今日或 Widget → 原生相机 → 分析 → 审核 → 详情。`DashboardScreen._consumeInitialWidgetAction()` 已支持快速相机；快速入口不能跳过 AI 审核与确认。

### 手动替代

来源 Sheet → 手动 → 可选我的食物 → 分析/审核 → 详情。相机拒绝、用户不拍照、图片失败都提供 `改用手動記錄`。

### AI 失败

分析 → 状态中心 → `重試` / `改用手動記錄` / `稍後處理` / 明确放弃。相片、描述、手动值和修改必须保留。

### 离线/待同步

输入 → offline → 本机草稿/餐点 → pending-sync → 状态中心 → syncing → saved 或 sync-failed。安全默认是只声明「已保留在此裝置」，不声明账号已储存；离线正式确认规则待确认。

### 健康授权

健康概览 → 权限说明 → 系统授权 → 健康状态。允许/部分允许/拒绝/无资料分别处理；拒绝不阻塞饮食。

### 我的食物

手动 → 选取器 → 搜索/筛选/排序 → 选取 → 返回手动 → 审核 → 储存。封存/修改模板不改变历史餐点。

### 历史/回馈

今日日期入口 → 历史 → 单日 → 餐点详情/回馈/趋势。回馈生成失败不阻塞餐点。

### 通知与冷启动

通知必须带 `taskId / objectId / date / intendedAction`。冷启动先恢复会话，再消费 intent；任务存在则进入对象页，已完成则详情，失效则状态中心。通知权限被拒绝时今日和状态中心仍可找回任务。

## 六、分类、搜索与筛选

- 分类原则：对象优先、日期其次、状态辅助。
- 餐点按日期、餐别、进食时间、来源组织；今日新到旧，历史新日期到旧日期。
- 我的食物：最近、常用、全部、有条码、已封存；不用大量长期横向 Tab，使用搜索、筛选、排序。
- 我的食物管理搜索范围：名称、品牌、条码；记录选取器为上下文搜索；不建立无明确任务的全局搜索。
- 排序：推荐、名称、使用次数、最近更新、最新建立；返回列表保留查询、排序和筛选。
- 无结果：`找不到符合「关键词」的食物` + `改用手動新增` / `用文字描述`；P2 可提供条码/营养标示。

## 八、P0/P1/P2 落地顺序与验收

### P0

三项 Root 导航与返回契约；今日工作台；来源与四种输入；AI 状态与后台恢复；全屏草稿审核；确认储存；餐点详情/编辑/删除；离线、空、错误、权限、保存失败和冲突基础状态；状态中心最小待处理入口。

### P1

状态中心完整分组；历史/趋势/回馈；Health Connect 授权/同步/部分授权/无资料/失败；饮水；我的食物选取器与管理；后台重启恢复、待同步和日志。

### P2

条码、营养标示、品牌搜索；Google；AI 高级设置；隐私、照片管理、导出/删除；更新、管理员、特殊人群提示。

### 验收任务

- 登录 → 今日 → 拍照 → AI 草稿 → 修改 → 确认储存 → 餐点详情。
- AI 完成未储存时不误导为完成；相机拒绝一步可手动。
- AI/保存失败保留内容，重试不重复。
- 离线显示新鲜度；后台任务在切换/锁屏/结束后恢复。
- Health Connect 拒绝仍可饮食；状态中心可从任务进入正确对象。
- 通知、冷启动、返回保持正确日期与上下文。
- 我的食物选取回原表单；封存不影响历史。
- TalkBack、动态字体、键盘、手势导航不遮挡关键操作。
- 冲突可比较和选择，不静默覆盖。

## 十、给交互与内容的输入

**交互**：复杂审核全屏；Sheet 只来源/短筛选/短确认；长任务持久且可恢复；每条路由定义进入、返回、完成落点；长按/滑动/拖曳有可见替代；通知以任务/对象恢复；食物选取与管理分开。

**内容**：固定使用 `餐點`、`飲食紀錄`、`AI 估算・待確認`、`確認並儲存`、`待同步`、`我的食物`；错误先说明是否保留资料再给动作；健康使用「目前进度」「与目标的差距」「记录中」；权限说明用途与影响；无结果提供手动/描述替代。
