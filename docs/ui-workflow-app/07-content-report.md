# UI 内容策略分析报告

> 范围：仅针对 Flutter Android 手机原生体验；不设计 Web，不修改代码。所有 UI 文案使用台湾繁体中文。

## 一、品牌语调

AI Food Diary 像一位懂行、诚实且不评判的健康记录助手：专业但不疏远，直接但不制造压力。

三条原则：

1. **先说事实，再说下一步**：明确资料是否已保留、是否已储存，避免用户猜测。
2. **AI 只提供估算，不替用户下结论**：使用「約」「估算」「待確認」，不把不确定写成事实。
3. **错误先安抚，再解释，再给方案**：先说明相片、描述、草稿或修改是否仍在，再提供重试或替代。

### 禁用词与替代

| 不使用 | 推荐替代 | 原因 |
|---|---|---|
| `較推薦／普通／建議少吃` | `目前資料較完整／資料仍可補充／可再確認份量` | 移除羞辱和饮食评判 |
| `吃錯／不健康／失敗` | `尚未完成／目前資料不足／操作未完成` | 描述状态，不评价用户 |
| `超標／不及格／落後` | `目前進度／與目標的差距／記錄中` | 避免健康焦虑 |
| `圖片` | `相片` | 统一台湾繁中 |
| `保存／存檔` | `儲存` | 统一产品动作 |
| `分析完成` | `AI 分析完成，尚未儲存` | 明确分析/储存边界 |
| `置信度／正確率` | `AI 信心度` | 不暗示结果正确 |
| `送出／提交` | `開始分析／確認並儲存／儲存變更` | CTA 说明具体结果 |
| `系統繁忙` | `目前無法完成這項操作` | 直接说明下一步 |
| `沒權限` | `尚未授權` | 准确且不责怪用户 |
| `好的／完成` | `知道了／返回今天的飲食／查看草稿` | 避免模糊动作 |

保留正式名称：`AI`、`Android`、`Google`、`Health Connect`、`TalkBack`；单位用 `kcal`、`g`、`mL`、`kg`；不直接展示 `Loading`、`Save`、`Syncing`。

### 空/错误/加载原则

- 加载：说明加载对象，避免只显示 Spinner。
- 空状态：说清楚为什么空，并提供唯一主 CTA。
- 错误：先确认内容是否保留，再提供重试或替代。
- 离线：使用中性/信息语气，不使用危险红色伪装错误。
- 同步：区分 `待同步`、`同步中`、`同步未完成`、`已同步`。
- 冲突：显示较新版本和可选择动作，不静默覆盖。

避免 `完成`、`送出`、`好的`、`確定`、`返回首頁`、单独 `繼續` 等模糊 CTA。

## 六、权限、通知、TalkBack 与本地化

### 权限文案

- 相机：`允許 AI Food Diary 使用相機，只用來拍攝你要記錄的餐點相片。`
- 相簿：`允許你選取要用來建立餐點紀錄的相片。`
- 通知：`允許通知，讓你在 AI 分析或同步需要處理時收到提醒。你仍可在狀態中心查看。`
- 拒绝：`尚未授權；你仍可使用其他記錄方式。`；动作 `前往設定`。
- 数量：`已選取 {n} 張相片，最多 5 張。`

### Android 通知

| 场景 | 标题 | 内容 | 点击后 |
|---|---|---|---|
| AI 完成 | `AI 草稿已準備好` | `午餐的 AI 估算已完成，請檢查內容後確認並儲存。` | 查看草稿 |
| AI 失败 | `AI 分析未完成` | `原始內容已保留，可重新分析或改用手動記錄。` | 状态中心 |
| 保存失败 | `餐點儲存未完成` | `你的修改仍保留，請重試儲存。` | 重试储存 |
| 同步失败 | `健康資料同步未完成` | `上次同步的資料仍保留，開啟查看原因。` | 状态中心 |
| 成功 | `餐點已儲存` | `你的飲食紀錄已更新。` | 查看餐点 |

通知不得展示完整敏感营养细节，不得说分析完成即自动储存。通知关闭后任务仍由今日和状态中心召回。

### TalkBack 与图片描述

- 草稿：`AI 估算，待確認。這是可編輯草稿，尚未儲存。`
- 用户修改：`食物名稱，滷肉飯。已由你修改。`
- 热量：`熱量，約 520 千卡。`
- 待同步：`餐點已保留在此裝置，待同步。動作：立即同步。`
- 相片：未确认 `使用者上傳的餐點相片，食物內容尚未確認。`；确认后才能写具体食物。
- Sheet/对话框焦点进入并返回触发元素；错误先读摘要再聚焦第一个字段。

### 长度/字体/日期

- 关键按钮控制在 2–8 个中文字或等价长度；不截断 `確認並儲存`、`AI 估算・待確認`。
- 状态卡标题一行，说明 2–3 行；更长文本进入详情。
- 食物长名视觉可省略，但 TalkBack 读完整名称。
- 支持 1.3–1.5 倍字体；固定 CTA 避让键盘、手势区、系统导航栏。
- 首次返回先收键盘，再次返回才触发未保存 Dialog。
- 日期：`2025 年 3 月 8 日（週六）`；紧凑 `3/8（週六）`；时间 `12:30`。
- 数值：`熱量約 520 kcal`、`蛋白質約 28 g`、`飲水 500 mL`、`體重 62.4 kg`；AI 估算使用 `約` 或范围。

## 七、首次体验与引导

- 首屏：`先記錄今天的第一餐` / `拍照、描述或手動輸入都可以。AI 會先整理成草稿，儲存前由你確認。` / `記錄飲食`。
- 不使用多页轮播；采用说明页 + 记录方式 Sheet。
- 相机/相簿权限只在选择对应方式时请求；Health Connect 在健康功能中请求。
- 今日空状态提供四种入口的平等说明。
- AI 分析中允许离开，状态中心可恢复。
- 昨日回馈改为今日页内卡片，提供 `查看昨日回饋` 与 `稍後處理`，不自动阻塞 Dialog。

## 八、内容风险、假设与验收

- 不使用 `AI 已正確辨識`、`準確分析`、`幫你判斷是否健康`；信心度不能包装成正确率。
- 台湾繁中统一 `相簿`、`相片`、`紀錄`、`儲存`、`週`。
- 不使用 `燃脂`、`發胖`、`吃太多`、`不健康`；不以红绿表达好坏。
- 长文案须考虑 1.5 倍字体；关键 CTA 不省略；动态内容必须 TalkBack 可读。
- 假设与待确认：离线正式储存定义、同步边界、AI 信心度/营养编辑、相片隐私、Health Connect 范围、通知策略、多设备冲突、删除撤销、地区时区单位、`記錄飲食`/`記錄餐點`是否分工。

### 验收样例

1. AI 完成显示 `AI 估算・待確認` 和 `尚未儲存`，不显示 `已儲存`。
2. 修改后显示 `已由你修改`，重新分析不覆盖。
3. 保存失败时相片、描述、草稿和修改都能恢复。
4. 连续点击确认不重复建餐点，按钮变 `正在儲存…`。
5. 相机拒绝后可进入相簿、描述或手动。
6. Health Connect 拒绝仍能完成饮食记录。
7. 断网显示 `目前離線`/`待同步`，不显示服务器已储存。
8. 通知关闭仍能由状态中心找回任务。
9. Back 首次收键盘，再次返回才提示未保存。
10. TalkBack 能读标题、字段、单位、来源、修改、状态和动作。
11. 字体 1.5 倍时确认、重试、状态、单位不截断。
12. 产品中不出现 `較推薦`、`普通`、`建議少吃`，不以颜色单独表达健康好坏。
