# UI 需求摘要

- **执行模式**：深度模式
- **产品名称**：AI Food Diary（AI 飲食記錄）
- **产品定位**：一个由 AI 辅助的跨平台饮食记录产品；用户拍摄或输入餐点后获得热量与宏量营养素估算，并通过每日总结与健康数据同步形成持续反馈。
- **目标平台**：Web（桌面 / 平板 / 响应式网页）与 Android Mobile App（Flutter）。两端共享视觉身份，但不强制共享布局或交互。
- **目标用户**：兼顾大众日常健康用户与健身/营养进阶用户；基础流程低门槛，进阶数据可逐步展开。
- **品牌调性**：温暖专业——可信、清晰、有食物温度；避免医疗化、冷冰冰的数据墙与过度游戏化。
- **核心功能（P0/P1/P2）**：
  - **P0**：登录/注册、首页与当日概览、拍照/手动记录餐点、AI 分析结果确认与修正、每日总结。
  - **P1**：热量与蛋白质/脂肪/碳水趋势、饮水与健康数据、体重/活动消耗、Health Connect 同步、常用食物。
  - **P2**：条码扫描、营养标示录入、个人食物库、AI 设置、Google 绑定、隐私与 App 更新。
- **关键页面/场景**：登录/注册、今日饮食仪表板、新增餐点、AI 分析结果、每日总结、营养与健康历史、常用食物、个人与设置。
- **共享设计系统必须定义**：品牌身份、颜色与语义色、字体层级、间距、圆角、层级/阴影、图标、无障碍、组件命名原则、交互人格、状态与反馈语言。
- **平台约束**：Web 遵循桌面/平板/Web 交互；Mobile 遵循原生移动交互，包括触控目标、安全区、手势、底部导航、Bottom Sheet、相机/扫码入口与移动信息密度。
- **技术背景**：Web 为 Next.js App Router + TypeScript；Mobile 为 Flutter Android；现有实现和截图是当前状态证据，不是新视觉硬约束。
- **约束与偏好**：本阶段不实现生产代码；最终规范需可分别供 Web 与 Flutter 落地，明确共享 token 与平台适配边界。
- **待确认问题**：品牌/Logo 资产、字体授权与深色模式支持留待规范决策项；本轮已确认用户、调性、范围、模式、搜索与额外专家范围。
