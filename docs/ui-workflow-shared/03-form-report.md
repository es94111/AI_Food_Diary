# UI 形态分析报告

> 阶段：深度模式 · 共享内容模型与平台化布局建议

## 一、形态总览

共享信息架构、内容模型、语义状态和核心流程，不复制页面布局：

- **Web**：持久主导航 + 工作区 + 可展开辅助面板，利用横向空间支持对比、编辑、历史和批量操作。
- **Android**：底部主导航 + 单列内容流 + 单手可操作的主要行动；复杂编辑采用全屏页，次级操作采用 Bottom Sheet。

现有基线：Web 有「飲食/健康/食物/設定」顶层导航；Android 已有「飲食/健康/設定」Material NavigationBar；现有缓存优先、SnackBar、Bottom Sheet、后台 AI、Health Connect 状态可复用。

## 二、跨平台布局原则

1. 共享内容模型，不共享容器形态。两端都使用日期、餐点、食物项目、AI 草稿、用户确认、健康数据、食物资产、同步状态等语义对象。
2. “确认”是独立阶段：输入中 → AI 分析中 → AI 草稿待确认 → 编辑中 → 用户确认 → 保存中 → 已保存/失败。
3. 所有输入方式进入同一餐点草稿模型：相机、相册、描述、手动、条码、营养标示、常用食物。
4. 摘要优先、细节按需展开：默认总热量、三大营养素、主要餐点、需要注意的估算项、同步状态和主要动作；详细假设和历史按需展开。
5. 今日是主上下文，历史是次上下文。Web 可用日期控件和周视图；Android 用紧凑日期选择与横向日期条。

## 三、关键页面形态

### 1. 登录/注册/首次资料

单栏聚焦表单；包含账号、Google、资料补全、隐私说明、就地错误。Web 适配键盘/自动填充/URL；Android 适配软键盘、安全区、返回。资料不足时允许稍后补充，但明确功能影响。

### 2. 饮食 Dashboard（日视图）

- **Web 桌面**：日期与导航、中央摄取总览/餐点列表/记录入口、右侧饮水/建议/同步/昨日总结。
- **Web 平板**：单栏为主，辅助模块折叠或下移。
- **Android**：单列内容流、固定底部导航、新增餐点为主要行动。

无餐点时展示“拍照记录”为主动作，保留手动/常用食物。无缓存显示结构化骨架；有缓存刷新显示更新时间；失败保留缓存并提供重试。

### 3. 周视图/历史

Web 上方日期与平均摘要，下方趋势图、每日摘要、选中日期详情；Android 单列趋势卡与日期条。缺失日期不以零值伪装，明确数据不足。

### 4. 餐点输入/捕获

Web 采用捕获工作区或大模态：来源、内容预览、补充信息、分析状态。Android 从主行动进入来源 Bottom Sheet，相机/扫码全屏，手动输入全屏。提交前不要求过多信息，精确模式作为高级选项。

### 5. AI 草稿确认

- **Web**：照片/来源、可编辑食物项目、营养总量的双栏审核器；旁边展示 AI 说明/置信度和重分析/保存动作。
- **Android**：多项目使用全屏编辑页，单项目可用高位 Bottom Sheet；底部固定确认区。

每项可改名称、份量、单位、热量、蛋白质、脂肪、碳水；重分析前说明可能覆盖范围；离开未保存时选择保留草稿、放弃或继续。AI 无结果提供手动新增和重拍；保存失败保留编辑。

### 6. 已保存餐点详情

Web 详情侧栏/独立页；Android 详情页/编辑 Bottom Sheet。区分已保存餐点与 AI 草稿；显示日期、来源、图片、营养、编辑/重分析/删除。

### 7. 健康 Dashboard

Web 顶部同步状态与关键摘要，下方健康分组网格和历史侧栏；Android 单列，顶部同步/权限。区分未授权、无设备数据、尚未同步、部分成功、数据过期。Web 展示结果，不假装直接完成 Android 权限授权。

### 8. 食物资产库

Web 搜索筛选 + 表格/列表 + 详情侧栏，支持批量封存与重复整理；Android 单列搜索列表，详情/编辑全屏或 Bottom Sheet，扫码为独立页。资产快速加入当前餐点草稿，不直接产生未知餐点。

### 9. 设置

Web 左侧设置分组 + 右侧内容；Android 设置列表 → 子设置全屏页。按个人资料/目标、AI、Google、健康、隐私、更新分组；敏感配置只显示存在状态，不显示原文。

### 10. 昨日总结/每日反馈

Web 使用非阻塞面板或独立详情；Android 使用可下拉 Bottom Sheet 或全屏页。首次提示不阻塞主 Dashboard，关闭后仍可召回；无数据、生成中、失败均提供可执行替代路径。

## 四、响应式断点（概念）

### 桌面 Web（建议 ≥1280px）

持久侧栏/宽导航；主工作区 + 辅助面板；AI 双栏/三段编辑；健康网格；资产表格/批量；设置分组。固定层不得遮挡保存动作。

### 平板 Web（建议 768–1279px）

折叠侧栏或紧凑 Tab；单栏为默认；辅助内容改抽屉/下移；AI 上下分区；资产列表 + 抽屉；健康两列或单列。

### Android（建议 <768px）

底部导航在安全区内；单列和拇指可达；新增为主行动；长编辑全屏，短任务 Bottom Sheet；核心表单不依赖横向滚动；图表提供文本摘要；保留系统返回和键盘避让。

## 五、页面模板

- **Dashboard 工作台**：页面上下文 → 主摘要 → 核心行动 → 分组内容 → 辅助反馈 → 召回入口。
- **捕获工作区**：来源 → 输入预览 → 可选补充 → 分析状态 → 草稿确认。
- **AI 草稿审核器**：原始输入 → 识别结果 → 可编辑字段 → AI 说明/置信度 → 重分析 → 保存确认。
- **列表 + 详情**：Web 列表 + 侧栏/抽屉；Android 列表 + 详情页/Bottom Sheet。
- **分组设置**：设置分组 → 当前说明 → 字段/开关 → 保存状态 → 风险提示/恢复。

## 六、导航形态

### Web

推荐长期形态为左侧主导航：飲食、健康、食物、設定。当前顶部胶囊导航可作为过渡；不要让它承担过多二级状态。

### Android

保留三项底部导航：飲食、健康、設定。“食物”从饮食记录流程或设置进入；新增餐点作为高频行动，不作为第四个目的地。

## 七、核心流程形态

拍照 → AI → 编辑 → 保存：Web 为 Dashboard → 捕获工作区 → 双栏审核器 → 定位到新餐点；Android 为主行动 → 来源 Sheet → 原生相机/相册 → 后台分析 → 全局状态/查看 → 全屏审核 → 固定确认 → 返回 Dashboard。

文字/手动、条码、营养标示都进入同一草稿；扫描结果先确认再加入餐点或保存资产。Health Connect 流程为健康页 → 权限/同步状态 → 授权 → 同步 → 完成/部分失败/重试；Web 展示同步结果，Android 完成系统授权。

## 八、容器层级

1. 应用外壳：认证、主题、时区、网络/缓存/同步、主导航。
2. 页面容器：标题、日期/筛选、主行动、页面级状态。
3. 功能区：摄取、餐点、健康、资产、AI、设置。
4. 内容容器：摘要卡、列表/表格、趋势图、表单、图片、详情。
5. 内容单元：餐点行、食物行、指标行、字段、标签、进度、按钮。
6. 状态层：Inline 错误、行级保存、SnackBar/Toast、Modal/Dialog、Sheet、加载、重试、同步。

## 九、信息密度

- 日常记录：餐点名称、时间、热量和三大营养素摘要默认可见；份量假设和 AI 说明展开。
- AI 审核：每个项目独立编辑；名称/份量优先；数值可修改；说明靠近结果；重分析与手动修改关系明确。
- 健康：关键指标、测量时间和来源首屏可见；趋势和原始数据按需展开；未知不等于零。
- 食物资产：最近使用/收藏优先；搜索、筛选、新增可见；Web 批量管理，Android 快速复用。
- 设置：按任务分组；保存、未保存、权限和敏感配置状态明确。

## 十、正式状态布局

### 空状态
说明原因 + 唯一主动作 + 可选替代。例如无餐点 → 拍照记录；无食物 → 从餐点保存/扫码/手动；健康无数据则区分未授权、未同步、设备无数据。

### 加载态
页面使用结构化骨架；局部请求局部替换；AI/同步长任务显示阶段并允许离开。缓存优先：有缓存先展示并标刷新；无缓存才骨架。

### 错误态
输入错误贴近字段；网络保留编辑并重试；AI 失败保留图片/描述并可手动保存；权限错误说明去处；部分同步显示成功/失败范围；保存失败不得清空草稿。

### 同步态
统一为未同步、同步中、已同步、部分完成、失败、数据过期、需要权限；出现在健康页顶部、饮食净热量/健康模块、Android 设置和 Web 健康说明中。

## 十一、平台推荐与避免

### Web 推荐
侧栏/双栏/抽屉；AI 表格/编辑器；资产搜索批量；健康历史对比；URL 保存日期/筛选；长任务可离开；键盘焦点和保存状态清晰。

避免：窄单栏卡片流浪费桌面；过小复杂弹窗；悬停才可见关键操作；动态背景遮挡任务；图表替代数值；伪装 Web 直接授权 Health Connect。

### Android 推荐
Material 3、系统安全区、返回手势、键盘避让；三项底部导航；相机优先；来源 Bottom Sheet；长编辑全屏；缓存优先；SnackBar 作为跨页低风险反馈；权限渐进解释。

避免：三栏/表格/侧栏缩小到手机；把所有入口塞到底部导航；短 Sheet 承载长编辑；启动时不可关闭总结；分析完成自动保存；主要按钮在顶部/滚动深处；忽略刘海、安全区和返回。

## 十二、组件/实现边界建议

Web 沿用 Tailwind 基础，补充无头组件规范；Android 继续 Flutter Material 3，以现有 `AppPalette`、`AppRadius` 和 Theme Extension 作为主题基础。跨平台共享组件语义、状态、token 和内容字段，不共享代码。暂不引入强约束大型 UI 库或以玻璃、渐变、高动效为核心的组件库。

## 十三、风险与下游交接

- Web 从窄单栏迁移多栏需先定义优先级和网格，不能简单横排所有卡片。
- Android 后台 AI 完成可能被错过：保留全局状态、SnackBar“查看”和待处理入口。
- 重分析可能覆盖修改：明确覆盖范围，保存原始输入与修改状态。
- Health Connect 时间/权限容易误解：所有指标显示来源和测量时间。
- 周平均与日总量容易混淆：标题、单位、说明明确。
- 食物资产重复：明确合并/封存/另存为新项目关系。
- 当前玻璃/渐变/动效需视觉阶段收敛。
- 移动底部导航、FAB、键盘和安全区需统一避让规则。
- Web 精确模式与 Android 能力差异需能力矩阵说明。

下游要点：IA 固化一级导航与食物归属；交互绘制统一草稿流程和恢复机制；视觉基于 globals.css/AppPalette 建 token 并验证暗色/对比度；内容统一估算、置信度、状态和错误；工程共享语义对象/状态枚举，不复制组件实现。
