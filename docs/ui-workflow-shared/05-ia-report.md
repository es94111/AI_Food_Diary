# UI 信息架构分析报告

> 阶段：深度模式 · 后续交互与内容设计的权威 IA 输入
>
> 标注：**[事实]** 来自仓库/上游报告；**[设计推断]** 为建议；**[待确认]** 会影响架构、命名或数据边界。

## 一、核心 IA 原则

1. 共享导航语义和信息模型，不复制导航承载。
2. 「新增餐点」是高频任务入口，不是一级目的地。
3. 「食物」是长期资产与选择辅助；Web 可独立管理，Android 不增加第四底部 Tab，但必须从记录流程可发现。
4. 待处理、草稿、同步、权限属于跨模块状态，需要全局状态入口，不能只埋在设置。
5. 领域核心是：日期 → 餐点 → 食物项目 → AI 草稿 → 用户确认 → 已保存餐点；健康数据、食物资产、同步任务为关联对象。
6. `review` 是“AI 已生成但尚未成为事实”的边界；只有用户确认后才进入 `saving/saved`。

## 四、页面信息层级

### 今日工作台

第一层：日期、新增餐点、今日记录摘要、已保存餐点、待处理提示。第二层：餐点时间线、营养摘要、饮水、每日反馈。第三层：详细宏量、健康来源、同步详情、历史入口。Web 可并列更多信息；Android 先呈现日期、核心摘要和主行动。

### 捕获工作区

第一层：拍照/相册/描述/手动、日期和餐点类型。第二层：最近/常用/收藏、条码/营养标示。第三层：单位、份量、备注、高级选项和图片隐私。

### AI 草稿审核

第一层：AI 结果、食物项目、份量、营养估算、编辑、确认保存。第二层：来源、估算等级、替换、增删、备注。第三层：详细字段、原始说明、图片和单位换算。命名建议“AI 草稿/审核 AI 结果”，不用暗示已确认事实的“分析结果”。

### 历史

日期为主索引；显示有记录、空、草稿、保存失败、离线待同步等状态。Web 适合月历/列表/比较，Android 适合日期选择 + 单日时间线。返回必须保留日期、筛选和滚动上下文。

### 健康

第一层：摘要、更新时间、授权/连接状态；第二层：营养、饮水、体重、活动；第三层：来源、同步日志、权限和无数据解释。区分未授权、无数据、过期、部分失败。

### 食物资产

第一层：搜索、最近使用、常用/收藏、新增；第二层：来源、分类、单位、列表；第三层：营养细节、条码/标签、编辑历史。无结果提供 AI 描述、手动新增、条码或营养标签替代路径，回到餐点草稿而不是死胡同。

### 设置

按用户目标分组：个人资料、偏好、AI、连接、隐私、关于；不按技术模块堆叠。高风险操作单独确认。

## 五、核心领域对象与生命周期

```text
User
└── Day
    ├── Meal
    │   ├── FoodItem
    │   ├── InputSource
    │   ├── AIDraft
    │   └── Confirmation
    ├── DailyFeedback
    └── HealthSummary
FoodAsset：系统/自定义/最近/常用/收藏/条码/标签
SyncTask：上传/分析/保存/离线/Health Connect/错误/重试
```

对象状态：

```text
idle → input → uploading → analyzing → review → saving → saved
异常：input → offline；uploading/analyzing → error；saving → error；saved → syncing → sync-failed
权限：permission-required → 授权 → syncing；permission-denied / empty
```

状态必须绑定对象和任务，不只存在页面上；`permission-denied` 不等于 `empty`，`offline` 不等于 `sync-failed`。保存失败保留草稿和编辑内容；是否允许离线创建待确认。

## 六、核心用户流

1. **首餐**：登录/注册 → 今日 → 新增 → 相机/相册/描述/手动 → AI → 草稿审核 → 编辑 → 确认保存 → 餐点详情/今日 → 每日反馈。离开后草稿进入待处理。
2. **常用食物**：今日 → 新增 → 食物选择器 → 最近/常用/收藏 → 确认份量 → 草稿 → 保存。选择资产也要确认份量，不直接成为事实。
3. **修正 AI**：今日/状态中心/草稿 → 审核 → 编辑 → 确认 → 保存；失败仍停留可编辑草稿。
4. **历史**：飲食 → 历史 → 日期 → 单日时间线 → 餐点详情；返回保留日期上下文。
5. **趋势**：健康 → 概览 → 趋势 → 时间范围 → 指标 → 某日/餐点。
6. **Health Connect**（Android）：设置 → 连接与同步 → Health Connect → 数据类型/系统授权 → 同步 → 健康概览。Web 只展示结果、时间与来源。

## 七、全局状态中心

Web 侧栏底部/顶部辅助区，Android 饮食页待处理 + 顶部状态入口。分组按用户下一步：

```text
需要我处理：草稿待审核、保存失败、权限待处理
系统处理中：AI 分析、保存中、健康同步
稍后重试：离线待同步、同步失败、AI 失败
已完成：最近保存餐点
```

每条显示对象、日期、状态、下一步和更新时间。不能只依赖 Toast/SnackBar。

## 八、搜索与食物资产

Web 有全局搜索（食物资产、餐点、历史日期）和上下文食物搜索；Android 主要在新增餐点、食物资产、历史中提供上下文搜索，不常驻全局框。首期可支持名称、品牌、自定义名、餐点名、日期、最近/收藏；后续条码、分类、营养范围、单位和来源筛选。

结果顺序建议：当前餐点 → 最近使用 → 常用/收藏 → 系统食物 → 自定义 → 创建自定义 → 条码/营养标示（P2）。无结果必须提供“检查拼写、用描述、手动添加、营养标签、扫码”。

## 九、Health Connect 边界

Android 负责系统授权、数据读取和同步状态；Web 负责展示来源、更新时间和过期状态，并引导到 Android，不能伪造授权。饮食记录不依赖健康授权。必须区分未授权、无数据、过期、部分成功和失败；数据类型、读写方向、回填范围待确认。

## 十、命名原则

按用户任务命名：“新增餐点”优于“开始分析”；“审核 AI 结果”优于“查看识别结果”；“确认并保存”优于“提交”。共享概念建议：日期、餐点、食物项目、AI 草稿、确认保存、食物资产、健康数据、同步任务、输入来源。状态标签：AI 估算、用户已修改、待确认、已保存、保存失败、离线创建、待同步、同步失败、数据过期、无数据、未授权。避免“违规、放纵、失败、不健康”等羞辱词。

## 十一、IA 风险与冲突

- 结构过深：一级只保留四个 Web 区域、三个 Android tab。
- Android 第四 Tab：当前建议不增加，需任务测试发现性。
- AI 事实边界：使用草稿/审核/确认，避免“分析结果”暗示最终事实。
- 状态分散：建立跨平台状态中心。
- Health Connect 阻塞：权限拒绝不影响 P0。
- 搜索死胡同：无结果回到统一草稿。
- 日期不一致：确定时区和日期权威来源，详情显示日期时间。
- 双模式分裂：若提供简洁/进阶，只改变披露层级，不改变对象、导航和流程。

冲突决策候选：Android 食物入口、每日反馈触发、AI 估算等级、离线创建、图片保存、Health Connect 范围、食物来源、Google 语义、深色模式、目标来源。

## 十二、验证计划

1. 架构走查：每个对象有创建、查看、编辑/确认、失败恢复、返回路径。
2. P0 测试：注册、拍照、修正、保存、保存失败恢复、离开后恢复、拒绝 Health Connect 后完成记录。
3. P1 发现性：常用食物、无结果创建、历史返回、趋势、区分未授权/无数据/过期/失败。
4. 跨平台对照：页面命名、状态生命周期、字段、日期规则、Health Connect 权限、返回、状态中心、空错态一致。
5. 在进入实现前确认：地区语言单位、时区、Android 食物入口、模式、AI 等级、图片策略、Health Connect 类型/读写/范围、目标/反馈、离线和草稿清理、Google、深色模式。

## 十三、最终结论

Web 采用「飲食/健康/食物/設定」侧栏工作区；Android 采用「飲食/健康/設定」底部导航；食物资产从上下文流程进入；AI 草稿审核是信息边界；状态中心负责所有可恢复任务；日期是饮食历史主索引；Health Connect 只影响健康数据，不阻塞饮食记录；搜索必须服务于记录闭环。
