# UI 交互体验分析报告

> 阶段：深度模式 · 交互行为、状态契约与平台验收
>
> 本阶段只定义交互行为，不实现生产代码。

## 一、交互人格与原则

交互人格：温暖、专业、克制、可信、不评判；动效冷静、轻快、功能性优先。每次操作及时反馈，AI 只提供建议，正式记录必须明确确认和保存。长任务可离开，中断可恢复，错误可行动。

核心原则：
1. AI 是助手不是裁判：所有结果标记为建议/草稿，可编辑、可取消、可重试。
2. 确认和保存是独立边界：分析完成不等于保存完成。
3. 状态是正式体验：空、载入、分析中、待确认、保存中、失败、离线、同步、权限都可发现、可理解、可恢复。
4. 默认简单、详情渐进披露；高频流程不依赖隐藏手势。
5. Web 强调键盘、信息密度、双栏与历史；Android 强调单手、相机、底部导航、Sheet、安全区和系统返回。
6. 健康反馈中性、具体、非羞辱；不使用“失败、吃错、违规”等判断词。

## 二、组件微交互

### 按钮

Primary 用于新增/拍照/确认并保存；Secondary 用于手动/详情；Outline 用于编辑/取消；Ghost 用于撤销/关闭；Destructive 只用于删除/清除；Icon-only 必须有语义标签。Web hover 120–160ms；Android 使用 pressed/ripple 80–120ms。Loading 保留文字，例如“保存中”；Success 以短暂“已保存”后回到稳定状态；Error 恢复可操作并提供重试。

### 输入与 AI 字段

Label 不由 placeholder 替代；字段始终显示单位、必填/可选和错误。AI 预填显示“AI 建议，可编辑”；用户修改显示“已调整”，不是错误色；错误贴近字段并说明如何修正；离开有未保存更改时提供继续、保存/确认、放弃。

### 列表和卡片

Web 可轻微 hover，Android 使用 pressed；卡片主内容可进入详情，编辑/删除独立可访问。草稿、分析中、待同步、保存失败、已保存都同时有文字与图标；删除需确认，移动左滑不直接永久删除，可归档或撤销。

### Dialog/Drawer/Sheet

Web Dialog 180–220ms，Drawer 220–280ms；Android Bottom Sheet 220–280ms，短任务用 Sheet，复杂 AI 审核用全屏。未保存表单、权限和冲突不能因遮罩点击直接丢失。Web 弹层焦点进入容器，Tab 循环，关闭回触发按钮；Android 返回先关闭 Sheet，审核页未保存时先确认。

## 三、AI 状态机与恢复

共享领域模型：日期 → 餐点 → 食物项目 → AI 草稿 → 用户确认 → 已保存。

```text
idle → captured → analyzing → review → review-unsaved → saving → saved
analyzing → analysis-failed
saving → save-failed
analyzing → offline/analysis-paused
saved → syncing → sync-failed
review-unsaved → restoreable-draft
```

状态契约：

| 状态 | 表现与可操作项 |
|---|---|
| idle | 新增入口；拍照、上传、手动输入 |
| captured | 显示输入已接收；更换、取消、开始分析 |
| analyzing | 阶段提示/已等待时间；可离开、查看其他页面、取消（是否支持取消待确认） |
| review | “AI 建议，可编辑”；编辑、增删、重分析、确认保存 |
| review-unsaved | “有未保存更改”；继续、保存、放弃 |
| saving | “保存中”；禁止重复提交，任务可幂等 |
| saved | 正式记录、时间、来源；查看/编辑/删除 |
| analysis-failed | 具体原因、重试、改手动；保留原始输入 |
| save-failed | 草稿仍保留；重试、稍后处理；不产生重复记录 |
| offline | 缓存新鲜度、本地草稿/待同步；不伪装已保存 |
| conflict | 显示本地/服务器差异，选择或合并；不静默覆盖 |
| permission-denied | 用途、重新授权、跳过；不阻塞饮食 |

恢复规则：离开分析继续后台；编辑离开保存可恢复副本但不成为正式记录；刷新/应用重启从服务器草稿或本地副本恢复并显示时间/来源/状态；网络断开保留输入和任务标识，恢复后手动继续/重试，避免无限重试；保存失败保留照片、原始文本、AI 建议和用户修改；跨设备冲突进入解决流程。

正式状态必须区分：恢复副本（防丢失）、待同步草稿（用户已发起保存但服务器未确认）、已保存记录（服务器确认）。

## 四、页面状态矩阵（行为契约）

### 今日饮食

- 加载：有缓存先显示并标时间；无缓存结构化 skeleton。
- 空：说明“今天还没有记录”，主 CTA“新增餐点/拍照”，次级手动/常用食物。
- 正常：日期、餐点、摘要、饮水、状态中心。
- 错误：保留缓存，说明可能非最新，提供重试。
- 离线：显示离线和待同步，不冒充服务器已保存。

### 新增/采集

默认突出相机，同时提供相册、文字、手动、常用食物。输入预览可重拍/替换；相机、格式、上传错误就地说明替代方案；离线可保留照片/描述草稿，明确 AI 需联网。

### AI 草稿审核

Web 双栏、Android 全屏。字段可编辑；AI 无结果提供手动新增/重拍；离线显示本地草稿和待联网保存；保存失败保留全部编辑。不存在或无权限时不泄露资源信息。

### 餐点详情

显示日期、餐点、食物、营养和来源；缓存显示时间；空餐点提供添加/删除；删除有确认和可撤销。

### 健康

显示授权/更新时间/数据来源；无数据区分未授权、已授权但没有数据、尚未同步、过期；失败可重试；Web 不提供伪造 Android 授权操作。

### 状态中心

分为“需要我处理、处理中、稍后重试、已完成”，每条显示对象、日期、状态、下一步和更新时间。离线时标明列表可能不是最新。

### 设置

缓存可显示；保存失败保留表单；离线本地偏好可标记待同步，安全/账户设置需联网；敏感数据不明文展示。

## 五、核心任务流程

### 登录 → 今日

提交显示“登录中”，成功后进入今日并聚焦标题；缓存优先；会话过期时先保护草稿再重新认证。Web 侧栏四项，Android 底部三项。

### 新增 → AI → 草稿

新增 → 选择拍照/相册/文字/手动 → 输入预览 → 开始分析 → analyzing（可离开）→ review。AI 结果标记“建议，可编辑”；原始输入可回看；重分析若会覆盖修改必须提前说明；无法识别提供手动路径。

### 草稿 → 保存

进入审核 → 修改显示未保存 → “确认并保存”进入保存中 → 成功进入 saved/餐点详情；失败恢复按钮并完整保留；返回显示继续、稍后处理或放弃。保存请求要幂等，连续点击不重复建餐。

### 长任务中断

分析可在健康页、后台继续；返回应用由状态中心恢复；超时显示仍在处理/可离开，不给虚假百分比；失败进入稍后重试，不自动无限重试。

### 离线与同步

离线显示缓存时间；允许本地编辑；保存标记待同步；网络恢复进入 syncing；成功更新来源/时间；失败进入稍后重试；冲突展示差异，不静默覆盖。离线 AI 不承诺，需要联网。

### Health Connect

Android 健康/设置 → 说明用途和数据类型 → 系统授权 → syncing → 成功/部分成功/无数据/权限拒绝；拒绝仍可饮食记录。Web 只展示结果、来源、更新时间并引导到 Android。

### 删除

Web Dialog/Android AlertDialog；说明范围、恢复性；成功列表移除并提供撤销；失败保留原内容；移动左滑只露出操作。

## 六、平台差异

### Web 桌面 ≥1280

侧栏 + 主工作区 + 辅助区；AI 双栏；表格/历史并列；URL 保留日期/筛选；键盘快捷键和可见焦点；hover 只增强不承载关键操作。建议 `Ctrl/Cmd+K` 搜索、`N` 新增、`Ctrl/Cmd+Enter` 确认（不在输入控件时）、Esc 关闭/确认未保存、方向键切日期（不抢输入焦点）。

### Web 平板 768–1279

折叠侧栏/抽屉；AI 双栏变上下单栏；不依赖 hover；触控区域也按 48px；侧栏焦点可进可回。

### Android <768

单列、底部「飲食/健康/設定」、相机优先、主行动单手可达；短任务 Bottom Sheet、复杂审核全屏；按压/ripple、系统返回手势、键盘避让、安全区/刘海/手势区；食物为上下文入口。主行动和底部固定栏不能重叠。

## 七、手势与键盘

Android 可用下拉刷新、Sheet 上滑展开/下滑关闭、日期横滑、图片双指缩放、列表长按批量、左滑归档/删除（需确认），但所有核心任务有可见按钮替代。Web 支持 Tab/Shift+Tab、Enter/Space、Esc、搜索/新增/保存快捷键；快捷键在输入控件聚焦时不抢行为。

## 八、动效与可访问性

动效：hover 120–160ms、按压 80–120ms、状态 120–200ms、Dialog 180–220ms、Sheet 220–280ms；保存成功 800–1200ms 后回稳定态；AI 用轻量骨架/阶段提示，避免无限 spinner 为唯一反馈。Web 遵守 `prefers-reduced-motion`，Flutter 遵循系统移除动画；减动画时取消位移、缩放、抖动、循环。

无障碍：完整键盘流程；Dialog/Drawer/Sheet 焦点进出并返回；页面路由焦点到标题；`aria-live`/Android announcement 读出分析、保存、同步；图标按钮有 label；正文至少 4.5:1、大字至少 3:1；Amber 不作小字号正文；营养/状态不只靠颜色；触控至少 48×48；字段有 label/单位/错误关联；TalkBack 能完成底部导航、Sheet、审核和保存；图片有替代描述。

## 九、风险与验证

风险：低端 Android 动效/图片/Sheet 掉帧；AI 延迟不稳定；草稿与保存混淆；离线和多设备冲突；敏感本地缓存；Health Connect 权限误解；日期/时区；AI 值/用户值和单位不一致；过多快捷手势增加复杂度。

验收：
- P0 完成登录→拍照/输入→AI 草稿→编辑→确认保存。
- 明确知道 AI 未保存；失败后草稿/照片/修改保留；离开后可从状态中心恢复。
- Health Connect 拒绝不阻塞饮食。
- 桌面/平板/Android 无横向溢出、遮挡或不可达操作。
- 在线/慢网/断网/恢复/超时、AI 成功/低置信/失败、保存失败/重复点击/会话过期/冲突均可恢复。
- 相机拒绝可图库/手动；无权限不泄露他人记录；删除有确认/撤销；日志不含照片、健康数据或认证信息。
- 键盘、TalkBack、系统大字、reduced-motion 和对比度通过。

待确认：取消 AI、草稿保存与跨设备策略、确认与服务器写入关系、待同步选项、多设备合并、照片策略、营养直接编辑/份量重算、日期时区、健康同步范围、最低 Android、删除撤销时长、是否通知长任务完成。
