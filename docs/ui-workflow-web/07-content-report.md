# 07-content-report.md

> 适用范围：AI Food Diary 的 Web application，包含桌面 Web、平板 Web 与移动 Web。不包含 Android、Flutter、原生 Mobile App 文案，也不涉及生产代码修改。本报告以台湾繁体中文、摘要优先、AI 可编辑估算、状态诚实与可恢复操作为基准。

## 1. Voice and Tone

### 人格

像一位懂饮食与资料的同事：专业但不疏远，直接但不冰冷；提供整理与估算，不替你评判。

### 三条原则

1. **先说发生什么，再说下一步**：`储存未完成。这份草稿仍保留。重试储存。`
2. **AI 是助手，不是裁判**：使用 `AI 估算`、`初步分析`、`待确认`，不使用 `正确答案`、`判定`。
3. **不评价人，只描述资料与进度**：使用 `目前记录`、`与目标的差距`、`尚未完整记录`，不使用 `超标`、`失败`、`吃错`。

### Do / Don’t

| Do | Don’t |
|---|---|
| AI 已完成初步估算，请检查内容后再储存。 | AI 已正确辨识你的餐点。 |
| 目前记录为 1,520 kcal，与今日目标相差约 380 kcal。 | 你今天热量超标了。 |
| 储存未完成，这份草稿仍保留。 | 系统发生错误。 |
| 目前尚未取得健康资料授权。 | 你拒绝了健康资料权限。 |
| 找不到「鸡胸」；试试其他关键字。 | 无资料。 |
| 已在此装置保留，尚未同步。 | 已储存。 |
| 确认并储存 | 完成、送出、好的 |

### 禁用词与混用

避免：饮食日记、饮食资料、食材、AI 结果、辨识完成、正确答案、置信度/正确率、保存/存档、图片/相册、添加、超标、不及格、吃错、违规、系统繁忙、Loading/Saving/Error/Success、AI 判断、保证/一定正确/精准计算。统一用：饮食纪录、餐点、食物项目、AI 分析草稿、AI 估算、AI 信心度（仅在正式冻结后）、已由你修改、已储存、待同步、我的食物、健康资料、状态中心、相片、相簿、营养标示、饮水、储存/新增。

- 使用「你」，不使用「您」。
- 操作与状态用繁中；保留正式名称 `AI`、`Google`、`Web`、`BMR`、`TDEE`。
- 首次出现写 `基礎代謝率（BMR）`、`每日總消耗量（TDEE）`。
- 技术错误码只在可展开技术信息中出现，不作为主要错误文案。

## 2. Messaging Principles

### AI

| 原则 | 建议 | 避免 |
|---|---|---|
| 结果先定义为草稿 | AI 分析草稿、AI 估算、待确认 | AI 结果、已完成纪录 |
| 说明不确定性 | 初步估算、目前无法辨识、请检查 | 已正确分析、完全理解 |
| 标示用户来源 | 已由你修改 | AI 结果错误 |
| 重分析前提醒 | 重新分析可能更新目前的 AI 估算 | 直接重新分析 |
| 过敏边界 | AI 无法确认食物是否含有过敏原，请以包装标示/专业建议为准 | AI 已确认安全 |

### 健康

优先使用 `目前进度`、`与目标的差距`、`目前记录`、`约`、`过去 7 天的记录中`、`资料来源`、`最后更新`；避免 `超标`、`不及格`、`达标失败`、`不健康`。先显示数值，再给中性解读；未设定目标时不显示距离；趋势只描述已记录资料，不代表完整健康状态或医疗诊断。

### 错误

错误三段式：

1. 发生什么。
2. 资料是否保留。
3. 下一步做什么。

例：`储存未完成。这份草稿与修改仍保留。请重试储存，或稍后从状态中心处理。`

### 储存/同步/权限/隐私

- 本机：`已在此装置保留`。
- 账号：`已储存`。
- `待同步`、`同步中`、`已同步`、`同步未完成` 分开。
- 不用 `已完成` 同时代指 AI 分析、储存、同步。
- 权限用 `需要授权`、`尚未取得授权`、`授权未完成`、`前往设置`、`稍后处理`；健康拒绝时补 `饮食纪录不受影响`。
- 隐私只承诺已确认的用途、保存、第三方传送、删除/管理；未确认前不承诺永久保存、绝对安全、完全匿名或自动删除。
- 表格标题用用户资料概念；筛选显示条件/数量/chips/清除；批量显示 `已选取 3 个食物项目`；破坏性操作使用完整动词。

## 4. CTA System

| 类型 | 推荐 | 使用场景 | 避免 |
|---|---|---|---|
| Primary | 记录饮食、确认并储存、立即同步 | 页面/流程主行动 | 开始、完成 |
| Secondary | 手动记录、查看详情、查看历史与趋势 | 替代/延伸 | 更多 |
| Outline | 编辑内容、重新分析、新增食物 | 可逆次要重要操作 | 处理 |
| Ghost | 稍后处理、取消、关闭、撤销 | 退出/延后/低风险 | 不要、跳过 |
| Destructive | 删除餐点、删除资料、批次封存 | 破坏性/高影响 | 移除、清掉 |
| Icon-only | 编辑餐点、关闭对话框、开启更多操作 | 工具动作 | 只有图示无名称 |

统一用「储存」不使用「保存」；`关闭` 不等于 `取消`；`删除餐点` 比 `删除` 清楚；`重试储存`/`重试同步` 比 `再试一次` 清楚。

| `offline` | 目前离线 | 查看状态 | 显示最后更新时间 |
| `pending-sync` | 已在此装置保留，尚未同步。 | 立即同步 | 不等于账号储存 |
| `error` | 操作未完成 | 重试 | 说明是否保留 |
| `permission-required` | 需要健康资料授权 | 前往设置 | 不阻塞饮食 |
| `permission-denied` | 目前未取得健康资料授权。 | 稍后处理 | 饮食不受影响 |
| `syncing` | 正在同步健康资料… | 查看状态 | 显示对象/时间 |
| `sync-failed` | 健康资料同步未完成。 | 重试同步 | 资料仍应保留 |
| `empty` | 尚无资料 | 记录饮食/新增食物 | 区分首次与筛选空 |
| `conflict` | 有两个版本尚未合并。 | 检视冲突 | 不自动覆盖 |

### 关键错误

- 网络：`目前离线。已显示最后更新于 {time} 的资料。恢复连接后再试。`
- 系统：`这项操作暂时无法完成。可用资料仍保留，请稍后再试。`
- 保存：`储存未完成。这份草稿与修改仍保留。` + `重试储存`。
- AI：`AI 分析未完成。可以重新分析，或改用手动记录。`
- 图片：`无法读取这张相片。请重新选取相片，或改用手动记录。`
- 权限：`目前无法存取这项资料。请确认账号权限，或返回可用页面。`
- 404：`这个页面不存在。可能已被移动或删除。` + `返回今天的饮食`。
- 表单：`请检查标示的栏位。错误会显示在对应栏位旁。`

### 成功

`餐点已储存`、`设置已储存`、`饮水纪录已储存`、`健康资料已更新，最后更新于 {time}`、`食物已封存`、`食物已还原`、`餐点已删除`、`草稿已在此装置保留，尚未同步。`。成功文案必须明确对象和储存层级，必要时提供撤销。

## 7. AI Copy Guidelines

- AI Review 按四层表达：原始输入 → AI 估算 → 用户修改 → 正式状态。
- 正常：`AI 已完成初步估算。请检查食物与份量，再储存这份纪录。`
- 不确定：`目前无法辨识这张相片中的食物。`、`份量为 AI 估算，请依实际内容调整。`
- 完全失败：`目前无法完成 AI 分析，可以重新分析，或改用手动记录。`
- 信心度未由模型团队冻结前，不显示百分比；如正式支持，只显示高/中/低并说明“不等于正确率”。
- 用户修改固定显示：`已由你修改；储存时会以你输入的内容为准。`
- 重分析前：`重新分析可能更新目前的 AI 估算。请先确认是否继续。`；有 dirty 时先询问如何处理。
- 过敏：`AI 无法确认食物是否含有过敏原。请以食品包装标示或专业建议为准。`
- 健康：`这些内容是个人纪录与趋势整理，不是医疗诊断或治疗建议。`
- 不说“这个食物适合你/安全/你应该停止吃/AI 判定不健康”。
- 来源标签：相片、餐点描述、手动记录、我的食物、营养标示、条码；手动记录不显示 AI 估算 Badge。

## 8. Onboarding / Help

### 低打扰三段式

1. `用相片或文字记录餐点` / 相片与手动都可以开始。
2. `先检查 AI 估算，再确认储存` / AI 是草稿助手，最终内容由你确认。
3. `在历史与趋势查看自己的节奏` / 趋势只整理已记录资料，不代表医疗判断。

CTA：`下一步`、`稍后处理`、`开始记录`；不使用“不要错过/立即完成健康管理”。

### 首次空状态

`先记录一餐，慢慢了解自己的饮食节奏。` / `你可以从相片、餐点描述或手动输入开始；AI 会先提供可编辑的估算。` / `记录饮食`。

### 状态中心说明

`状态中心会集中显示待确认草稿、储存与同步进度，以及需要你稍后重试的项目。` / `重要状态不只通过短暂提示显示，你可以随时回到这里查看进度。`

### 快捷键说明

| 快捷键 | 说明 |
|---|---|
| `Ctrl/Cmd+K` | 开启全域搜寻 |
| `N` | 新增餐点 |
| `Esc` | 关闭目前视窗；有未储存内容时会先提醒 |
| `Ctrl/Cmd+S` | 储存目前变更 |

补充：`在输入框中编辑文字时，快捷键不会触发页面操作。`

### 相片隐私

`相片会用于建立这次 AI 分析草稿。相片的保留、删除与资料使用方式，请参阅隐私与资料设定。` 只有在产品政策确认后才补充第三方服务、保存期限或删除承诺。

### Help

- `AI 会根据相片或餐点描述，产生食物、份量与营养的初步估算。估算可以编辑，也必须在储存前由你确认。`
- `相片角度、份量与烹调方式可能影响估算。确认可以让正式纪录更接近你的实际餐点。`
- `可能是尚未授权、目前没有资料、资料尚未同步，或最后更新时间较久。请先查看资料来源与最后更新时间。`

## 9. Phrases to Avoid

| 类别 | 避免 | 建议 |
|---|---|---|
| 羞辱 | 你今天吃太多了、不及格 | 目前记录与目标有差距、尚未完整记录 |
| 健康焦虑 | 超标 | 目前记录为 {value}，与目标相差约 {difference} |
| AI 过度承诺 | AI 已正确辨识 | AI 已完成初步估算 |
| AI 裁判 | AI 判定不健康 | 目前记录与目标的差距 |
| 假精确 | 523.78 kcal | 约 524 kcal |
| 模糊成功 | 完成 | 餐点已储存 |
| 技术泄漏 | Error 500/API timeout | 这项操作暂时无法完成 |
| 甩锅 | 系统繁忙 | 储存未完成，草稿仍保留，请重试储存 |
| 模糊空 | 无资料 | 今天还没有饮食纪录 |
| 词汇混用 | 保存、图片、食材 | 储存、相片、食物项目 |
| 过度承诺 | 完全安全、一定准确 | 请检查 AI 估算 |
| 医疗化 | 你需要控制饮食 | 目前记录与设定目标有差距 |
| 强迫 | 立即完成健康管理 | 记录饮食 |

## 10. Localization / Content Risks

- 全站台湾繁中；使用「储存、相片、相簿、饮食纪录、食物项目、营养标示、饮水」。
- 日期默认西元年；完整日期 `2025 年 3 月 8 日（周六）`，短日期 `3/8（周六）`；相对日期要能展开完整日期/时间；跨午夜、睡眠、同步需按用户时区。
- 使用 `kcal/g/mL/kg`；AI 用「约」或范围；数值和单位有空格；统一小数位与目标来源。
- 长中文、长食物名、品牌、日期、错误文案可换行；放大 1.3–1.5 倍不截断 CTA/状态/单位；Icon-only 有 accessible name。
- 图表同时有标签、数值、图例；相片替代文字不得把 AI 推测写成事实；重要错误不只 Toast。
- 饮食、相片、体重、睡眠、活动、健康资料属敏感个人资料；不在 URL、日志或状态文字泄漏不必要内容。
- 条码、营养标示、Google、导出删除、信心度、健康同步范围、跨设备草稿等未确认功能，不应提前展示承诺性文案。
